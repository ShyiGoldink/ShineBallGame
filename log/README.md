## 这里是项目框架指南，你可以在这里得知这个项目的开发指南

*文档在哪*
* `log/FunctionGuide.md`：日常用法——数据格式、组件总表、状态机、事件总线、Spine、约定与坑。
* `log/Architecture.md`：项目结构、依赖方向、现状清单，以及**耦合与偏离自查**（审计用）。

*开发工具*
Godot引擎v4.7.1自编译版本

*项目目标*
本项目旨在用户可以通过Json的方式，基于数据驱动来创造出不同的小球对象。

*项目设计*
由于游戏引擎天然存在组件功能，因此，直接把每个功能都设计成一个组件，然后在读取配置之
后进行装配是更好的选择。
组件以小球为中介，通过信号进行传递
下面是如何进行装配：
对于一个小球，它的基础是“状态”，而“状态”下可以有状态和行为。
状态的切换逻辑分为条件和循环。
每个小球至少需要下面的几个状态：
登场-移动-死亡
建议将攻击作为移动的子状态
可以作为条件的信号需要进行额外的注册，并在程序编译时写入到文本文件中。
每个行为都是单独的组件，包括攻击/无敌/受伤等。行为之间可以并行和串行。
每个组件需要单独的编号，并且要自描述：编号、类型名、说明、前置组件。
前置组件写的是“没装配它这个组件就跑不起来”的依赖，不是处理顺序。受伤现在也是一个组件，
无敌并不依赖它：两者在小球的事件链上占据不同的优先级，谁先处理这次伤害由优先级决定。


*项目结构*
res://assets/scripts/basic 放基类：小球、事件中心、组件基类等。
res://assets/scripts/components 放具体组件，按移动模式、攻击模式等进行区分。
