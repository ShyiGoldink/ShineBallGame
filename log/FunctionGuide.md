## 一局是怎么跑起来的

1. `index.tscn` 起来，`IndexManager` 管两个页面：`Index`（主菜单）和 `Select`（选球）。
2. 选球页左右各一个 `BallPicker`，各自选一个球、各自确认；双方都确认后"开始游戏"才可点。
3. 点开始 → `GameManager.StartGame(玩家1的球id, 玩家2的球id)` 记下选择并切到 `game.tscn`。
4. `Game` 从 `GameManager` 拿两个 id，用 `BallAssembler` 装配两颗球，摆到左右出生点。
5. 战前互挂：A 的 `enemycomponents` 挂到 B 身上，B 的 `enemycomponents` 挂到 A 身上。
6. 倒计时 3 秒（这期间球是"登场"状态，不会动）→ 对每颗球调 `FinishSpawn()`，球进入"移动"状态开始跑。
7. 只剩一个阵营活着 → 结算：`GetTree().Paused = true` 暂停，显示结果和"按任意处退出"。
8. 按任意键/点任意处 → `GameManager.ReturnToMenu()`（先解除暂停再切场景）回到主界面。

## 数据放在哪

游戏运行时读的是 `user://` 下的数据，不是仓库里的那份：

| 位置 | 用途 |
| --- | --- |
| `res://assets/data/...` | 仓库里的**默认数据**，只在新玩家第一次运行时补过去 |
| `user://balls/<球id>/` | 运行时真正读的小球数据 |
| `user://scene/` | 场景参数（暂时只有 arena.json，还没被读） |

补数据在 `Bootstrap`（自动加载）里执行，规则是**只补缺、不覆盖**：目标已经存在的文件永远不动，新版本新增的文件会自动补上。

想知道 `user://` 在系统里的真实路径，用 `UserData.Global(UserData.Balls)` 打印一下（Windows 上大概是 `%APPDATA%\Liya\app_userdata\ShineBallGame\balls\`）。

**这带来一个必须记住的后果**：改仓库里的 `balldata.json` 不会影响已经跑过游戏的机器。想立刻生效，直接改 `user://` 里那份，或者把 `user://` 里对应的球目录删掉，让补数据重新复制一次。

## 小球的数据格式

一个球一个文件夹，文件夹名就是球的 id（英文，选球界面和调试信息里都用它）：

```
assets/data/balls/NormalBall/
├── balldata.json
└── resource/
	└── avatar.png
```

`balldata.json` 的字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `name` | 字符串 | 显示名。会填进 `Ball.DisplayName`，数据面板和按钮上显示的就是它 |
| `hp` | 数字 | 血量上限，同时也是开局血量 |
| `type` | 数字 | 外观类型：1 = png，2 = spine（Spine 的文件也放这个球的 `resource/` 里，见「Spine 扩展」） |
| `spine_scale` | 数字 | 只有 `type = 2` 用：骨架整体缩放，配 `150 ÷ 角色在 Spine 里的高度` |
| `selfcomponents` | 对象 | **自己的组件**。键是组件编号（字符串），值是这个组件的参数对象 |
| `enemycomponents` | 对象 | **挂到对面身上的组件**，格式同上 |

现成的例子：

```json
{
  "name": "ball",
  "hp": 1200,
  "type": 1,
  "selfcomponents": {
	"2001": { "damage": 100 },
	"1001": { "speed": 900 },
	"4001": {}
  },
  "enemycomponents": {}
}
```

`"4001": {}` 是空参数写法（普通受伤没有参数）。参数不写就用组件里的默认值。

## 组件总表

编号约定：`1xxx` 移动类，`2xxx` 攻击类，`3xxx` 防御类（还没做），`4xxx` 行为类，`5xxx` 形态类，`6xxx` 控制类。

### 移动类

#### 1001 movement.normal（普通移动）

给一个初速度和初始方向，之后匀速直线前进，撞到东西按反射弹开（相对法线对称），速度大小不变、不衰减。只在**移动状态**下驱动小球，其它状态（登场/受控/攻击/死亡）一律停住。

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `speed` | 数字 | 200 | 速度，像素/秒 |

方向目前**不从 Json 读**：留空就是开局随机挑一个斜方向（20°~70° 的四个象限，保证两个分量都不小，免得两颗球都在水平/垂直线上跑、永远撞不到）。想让它可配，在 `NormalMove.ApplyParams` 里加一行读 `direction` 就行。

### 攻击类

#### 2001 attack.collision（碰撞攻击）

敌人进入检测圈就调用对方的 `TakeDamage`。规则：**不看攻击状态**（任何时候都能打）；撞到自己不算；同阵营（`Group` 相同）不算敌人；自己死了就不再打人。

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `damage` | 数字 | 10 | 每次碰撞造成的伤害 |
| `sound` | 字符串 | 空（不播） | 打到敌人时播的音效文件名或路径 |

它还有个 `Group` 字段，**由装配器从球身上填**（不是 Json），用来判断敌我。

音效配置长这样：`"2001": { "damage": 100, "sound": "hit.wav" }`。文件放在球自己的 `resource/` 里，找的顺序是：

1. 带协议头的（`user://...` / `res://...`）原样用；
2. 不带协议头的，先找这颗球自己的目录：`user://balls/<球id>/resource/<名字>`；
3. 还找不到就当成 `user://` 下的相对路径：`user://<名字>`。

认 `.wav` / `.ogg` / `.mp3` 三种，直接读文件，不走 Godot 的导入流程（跟 `avatar.png` 一样；放仓库里那份会被补数据复制到 `user://`）。播放时机是**这一下真的打到敌人之后**——撞到自己、同阵营、自己已经死了都不响；默认只放一遍（加载时会把循环强制关掉）。加载和播放都在 `SoundTool` 里，同一个文件只读一次，播放器挂在组件自己身上，一个组件一个。

#### 2002 attack.egg（下蛋攻击）

每隔 `cd` 秒进入一次攻击状态；进入之后过 `windup` 秒产下一颗蛋；攻击状态一共持续 `attack_time` 秒（这段时间是留给 Spine 动画的，没有动画配 0.2 就行），然后回到移动状态。

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `cd` | 数字 | 5 | 两次进入攻击状态的间隔（秒）。它一直在走，前摇和攻击状态里都不暂停 |
| `windup` | 数字 | 1 | 前摇（秒）：进入攻击状态后过多久产蛋 |
| `attack_time` | 数字 | 0.2 | 攻击状态持续多久。实际取 `max(attack_time, windup)`——比前摇短的话，前摇还没走完球就回移动状态了 |
| `egg_id` | 数字 | 无 | 蛋上挂哪个组件（组件编号） |

细节：

* **蛋不是球**：它就是一个普通节点——`Area2D` 当检测圈 + 一张图；长什么样、多大、干什么，全由 `egg_id` 指的那个组件自己搭（见 `2003`）。所以它**不进 `balls` 组、不参与胜负判定、没有血量**，也不是实体（别人碰不到它，只能它碰到别人）。
* 到点了但球不在移动状态（登场中、受控、还在攻击中）时，计时停在 0，等能打的那一刻立刻补上，不会丢这一次。
* 只有死亡会取消这次前摇。"回到移动状态"是攻击演完了，不算打断。
* 蛋还没有自己的数据：想换一种蛋就写一个新组件（`egg_id` 只能带一个组件）。

#### 2003 attack.shift（屎蛋）

撞到敌人时把它切成**受控状态**（这就是减速的入口），同时连着**若干秒**（默认 5）**每秒**造成对方**最大生命值的 1/20**（单次最多 100 点）的伤害。伤害走对方自己的受伤链打过去，所以对面挂了 `4002` 就会紫一下。

蛋长什么样也归它管：默认 `resources/shit.png`、显示 100×100 像素（碰撞圈一起改成 100 的直径）。蛋没有自己的数据目录，所以"这颗蛋是什么"就写在这个组件里——换个蛋，就是换一个 `egg_id` 指的组件。

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `texture` | 字符串 | `res://resources/shit.png` | 蛋的素材。`res://` 开头当资源加载，`user://` 那种直接读文件 |
| `size` | 数字 | 60 | 蛋显示多大（像素，按素材长边算），检测圈跟着一起改 |
| `duration` | 数字 | 5 | 效果持续几秒：对面受控这么久，这段时间里每秒跳一次伤害 |
| `tick_interval` | 数字 | 1 | 隔几秒跳一次伤害 |
| `damage_ratio` | 数字 | 0.05 | 每次跳对方最大生命值的多少（0.05 就是 1/20） |
| `damage_cap` | 数字 | 100 | 单次伤害上限 |

细节：

* **它不是球，也不是实体**：整个东西就是"`Area2D` + 一张图"。所以不会推开、也不会挡住任何球（**包括下它自己的那颗球**），别人也碰不到它——只有它靠检测圈感知谁撞上来了（检测圈半径 = 显示大小的一半 × 1.2；60px 的蛋就是半径 36）。
* 撞上就立刻疼一下，之后每秒一次；重复撞到会把时间重新计时，不会叠加。
* **效果走完自己消失**：5 秒跳完、或者对面死了，这颗蛋就 `QueueFree` 掉。用 `QueueFree` 而不是 `Free`——触发是在 `Area2D.body_entered` 的回调里跑的，当场删节点会把正在派发信号的那套东西一起掀掉。
* 减速（`6001`）和中毒染色（`4002`）是挂在**对面身上**的，所以蛋消失不会把效果一起带走。
* 没人碰过的蛋会一直留在场上（它不进 `balls` 组，所以不会影响胜负判定，只是占个位置）。要加"N 秒到期自动消失"，说一声。
* **减速真正的动作在对面**：蛋只负责"切成受控"，接管那一段移动的是对面身上的 `6001`（见「控制类」）。

### 行为类

#### 4001 behavior.normal_damage（普通受伤）

受伤链的最后一环：直接把血量扣掉，然后返回 `false` 阻塞后面的处理函数。装配时被注册到 `EventName.take_damage` 上，优先级 `DamagePriority.NormalDamage`（500）。

没有参数，写 `{}` 或直接省略参数对象都行。

#### 4002 behavior.poison（中毒染色）

受伤链里夹在护盾（700）和一般扣血（500）中间的那一环，优先级 600（`DamagePriority.DamageOverTime`）。它**不阻塞**：只把球染成紫色、过 `tint_time` 秒褪回白色，伤害照旧往后面传、由 `4001` 扣掉。

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `tint_time` | 数字 | 0.2 | 染紫持续多久（秒） |

用的时候注意：**要挂在"被打的那颗球"身上**——直接写它的 `selfcomponents` 可以，由攻击方写在 `enemycomponents` 里让装配器挂过去也可以（`pulipuli` 就是这么配的）。没挂就不会变色，毒伤照走。

### 形态类

#### 5001 shape.circle（圆形碰撞箱）

把球的碰撞圈 / 命中圈改成指定半径。**不写参数就什么都不做**，用预制体里那套默认圆——默认值只留在 `NormalBall.tscn` 里，代码和场景不会各存一份数字（跟数据的"只补缺、不覆盖"一个道理）。

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `radius` | 数字 | 0（= 用预制体的 75） | 物理碰撞圈半径 |
| `hit_radius` | 数字 | 0（= 用预制体的 90） | 命中检测圈半径。只写了 `radius` 时按 1.2 倍跟着走，保住两个圈的比例 |

例：`"5001": { "radius": 60 }` → 碰撞圈 60、命中圈 72。

为什么留这个口子：个别球的判定比例可能不一样（龙比虫子占地大一点），或者运行中要改形状（成长、缩水、护盾期间判定变大）——后者改预制体根本做不到。

**注意：装配时必须先复制形状再改。** 预制体里那个 `CircleShape2D` 是所有球共用的同一个资源（`resource_local_to_scene = false`），直接改半径会让场上一屏的球、乃至之后每个新球一起变。装配器的 `SetCircleRadius` 就是干这个的。

#### 5002 look.spine（Spine 外观）

`type = 2` 的球由装配器自动挂上它（不用写进 Json）：在球的 `resource/` 里找 Spine 资源，然后跟着球的五个状态切动画。

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `scale` | 数字 | 1 | 骨架整体缩放，一般直接用 Json 里的 `spine_scale`，不用手写这个组件 |

细节见「Spine 扩展」里的「type=2 的球怎么用 Spine」。

### 控制类

#### 6001 control.slow（减速）

挂在**被打的那颗球**身上——攻击方在自己的 `enemycomponents` 里配好，装配时被挂到对面。

它跟移动类组件是一个套路，只是各管一个状态：

| 状态 | 谁来驱动球 | 速度 |
| --- | --- | --- |
| 移动（`Move`） | `1001 movement.normal` | 全速 |
| 受控（`Controlled`） | `6001 control.slow` | 原先的 30% |

所以减速**不是靠挨打触发**的，是靠状态：蛋碰到球时把球切成受控（`Ball.BeControlled`），这个组件听见状态变化就接管这一段的移动——方向不变、速度乘 `speed_scale`；受控时间走完（自动回移动状态）再把速度还原。中途撞墙照样反弹（和 `1001` 共用 `BallMovement`）。

**球身上一个控制类组件都没挂时，受控就是"定身"**（没人驱动它，球停住）。也就是说：受控状态只说"谁被接管了"，**接管之后怎么动，由控制类组件决定**。

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `priority` | 数字 | 0 | 注册到状态变化事件时的优先级（别的状态监听都是 0，一般不用改） |
| `speed_scale` | 数字 | 0.3 | 速度压到原先的多少 |

细节：

* 接管那一刻记下"原先的速度"当基准，撒手时还原，所以受控期间反复挨打也不会越减越慢（30% 再 30% 就成 9%）。
* 静止的球（速度为 0，比如还没过登场倒计时）没什么可减的，接管了也不会动。
* 一颗球上现在挂**两个**控制类组件的话，两个都会各驱动一次——球会跑得比预期快，别这么配（要支持"多个控制效果抢方向盘"得在球那边做个登记，还没做）。

## 组件基类 BallComponent

所有组件都挂在球节点下面，继承 `BallComponent`，必须自描述：

| 成员 | 说明 |
| --- | --- |
| `Id` | 唯一编号，Json 里用的就是它 |
| `Type` | 类型名，形如 `"attack.collision"` |
| `DisplayName` | 显示名（默认等于 Type） |
| `Description` | 一句话说明 |
| `Requirements` | 前置组件：没装配它这个组件就跑不起来（写依赖，不是处理顺序） |
| `ApplyParams(字典)` | 装配时把 Json 里的参数读进自己的字段 |

组件内部用 `GetParent()` 拿球，所以**必须挂在球下面**。

## 状态机

状态是定死的几种（`BallState`），不开放给用户自定义，因为所有组件都靠"现在是什么状态"决定自己该不该干活：

| 状态 | 含义 |
| --- | --- |
| `Spawn` | 登场：刚上场，还没开始行动；开局就是它 |
| `Move` | 移动：自己动的球，移动类组件只在这个状态驱动小球 |
| `Controlled` | 受控：控制类组件只在这个状态响应输入（还没做控制组件） |
| `Attack` | 攻击：有动作的攻击走这里（见 2002）。移动类组件在这期间不驱动球，所以球会停住，时长由攻击组件定 |
| `Dead` | 死亡：终点，不再接受任何状态切换 |

规则：

* 当前状态是**私有**的，外面只能通过公开方法改，或者订阅状态事件；
* 每次改状态之前先判断当前状态（比如死人不能被拉回移动状态）；
* 血量扣到 0 或以下会自动进入 `Dead`，同时把速度清零；
* 公开方法：`FinishSpawn()`（登场 → 移动）、`BeControlled(duration, repeat)`（进入受控，`ControlRepeat` 有 `Reset`/`Add`/`Ignore` 三种处理方式）、`BeginAttack(duration)`（进入攻击，时间到自动回移动状态；只有移动中能进）；
* **受控状态只负责"换人驱动"**：移动类组件在受控状态下不驱动球，所以这段时间由控制类组件接手（见 `6001 control.slow`，慢速前进）。一颗球没挂任何控制类组件时，受控就是定身。
* 只读查看：`Ball.State`。

## 小球身上的事件总线

每个球有一个 `BallEvent`（`Ball.Events`），组件之间通过它通信。注册的处理函数按 `priority` 从大到小执行，**返回 `false` 就阻塞**后面的处理函数，返回 `true` 继续。

| 事件 | 载荷 | 说明 |
| --- | --- | --- |
| `take_damage` | 伤害值（float） | 扣血走这里。整条链由优先级决定谁先处理 |
| `state_changed` | 新的 `BallState` | 状态变化。通知类事件，处理函数一律返回 `true`，否则会把后面组件的收听一起堵掉 |

伤害链的优先级表（`DamagePriority`，数值越大越优先）：

| 数值 | 名称 | 说明 |
| --- | --- | --- |
| 1000 | `AbsoluteImmune` | 绝对免疫（无敌）：阻塞，不扣血 |

## 小球预制体

所有球共用 `assets/scene/NormalBall.tscn`，贴图在运行时按球自己的目录换：

| 节点 | 类型 | 说明 |
| --- | --- | --- |
| 根节点 | `CharacterBody2D` | 挂 `Ball.cs`，碰撞、移动都靠它 |
| `Body` | `Sprite2D` | 贴图。装配时换成 `resource/avatar.png`；场景里那张只是默认值 |
| `Shape` | `CollisionShape2D` | 物理碰撞：圆，半径 75（球直径 150）。想按球改就加 `5001 shape.circle` |
| `HitArea` | `Area2D` + `CollisionShape2D` | 碰撞检测：圆，半径 90。比球体稍大是故意的——`MoveAndCollide` 会把球停在"刚好接触"的位置，等大就永远差一点点触发不了。半径同样可以被 `5001` 改 |
| `HealthBar` | `ProgressBar`（挂 `HealthBar.cs`） | 血条，在球下方 10 像素，按剩余百分比换颜色（满白/不满黄/50%橘/25%红） |

## 如何自定义一个小球

1. 在 `assets/data/balls/` 下新建一个文件夹，名字就是球的 id（例如 `FastBall`）。
2. 放一个 `balldata.json`，按上面的字段写：名字、血量、外观类型、自己的组件、给对面的组件。
3. 放 `resource/avatar.png`——它同时是选球界面的头像和球在场上用的贴图，建议用正方形。要音效就再往 `resource/` 里放音频文件（`.wav` / `.ogg` / `.mp3`），然后在组件参数里写 `"sound": "文件名"`。
4. 把项目跑一次（或者删掉 `user://balls/<球id>/` 再跑），补数据会把新球复制到 `user://`。
5. 进游戏，选球界面会自动多出一个按钮，点它就能用这个球开打。

想让球有别的行为，就往 `selfcomponents` 里加组件编号和参数；想给对面添堵，就写到 `enemycomponents` 里。

## 如何新增一个组件

1. 在 `assets/scripts/components/` 下写一个类，继承 `BallComponent`，文件**必须**和类同名（例如 `Burn.cs` → `class Burn`）。
2. 挑一个没被占用的编号（1xxx 移动 / 2xxx 攻击 / 3xxx 防御 / 4xxx 行为 / 5xxx 形态 / 6xxx 控制），实现 `Id`、`Type`、`Description`。
3. 自己的参数写成公开字段，并重写 `ApplyParams` 从字典里读（用 `JsonTool.GetValue(parameters, "键", 默认值)`）。
4. 在 `ComponentLibrary.Create` 里加一个 `case 你的编号: return new 你的组件();`。
5. 如果这个组件需要接线（连信号、注册事件、填字段），在 `BallAssembler.Wire` 的 `switch` 里加一个分支。
6. 现在就能在 `balldata.json` 里用编号引用它了。

`BallAssembler` 目前负责的接线：**碰撞攻击**填 `Group` 并把 `HitArea` 的 `body_entered` 接上；**普通受伤**按优先级注册到 `take_damage`；**圆形碰撞箱**按参数改两个圈的半径（改之前先复制形状）。其它组件默认什么都不接。

## Spine 扩展

编辑器能用的 Spine 是官方 GDExtension，放在 `addons/spine-godot/`（`4.3-4.7.1 stable`，带编辑器/调试/发布三套、各平台都在）。

* **不用在 `project.godot` 里"启用"它**：引擎扫到 `.gdextension` 就会加载，`.godot/extension_list.cfg` 只是自动生成的缓存（`.godot/` 本来就不入库）。
* 认得的后缀，导入后分别是这两种资源：

| 后缀 | 导入成 |
| --- | --- |
| `.atlas` | `SpineAtlasResource` |
| `.spine-json`、`.spjson` | `SpineSkeletonFileResource` |
| `.skel`、`.spskel` | `SpineSkeletonFileResource`（二进制） |

* 用法：新建一个 `SpineSkeletonDataResource`（存成 `.tres`），把 `atlas_res`、`skeleton_file_res` 指过去，再赋给 `SpineSprite` 节点的 `skeleton_data_res`；播放动画走 `get_animation_state()`。
* 新放进工程的 `.atlas` / `.spine-json` 和图片一样要过一遍导入（打开编辑器，或跑一次 `--import`），否则运行时加载不到。

### 动画与美术的约定

球的外观资源放在 `user://balls/<球id>/resource/` 下，**不走 Godot 的导入流程**（导入器只在 `res://` 生效），所以运行时要现场构建：`SpineAtlasResource.load_from_atlas_file(路径)` + `SpineSkeletonFileResource.load_from_file(路径)` → 塞进 `SpineSkeletonDataResource` → 赋给 `SpineSprite.skeleton_data_res`，动画用 `get_animation_state().add_animation(名, 延迟, 循环, 轨道)`。按球 id 缓存一份，同一种球的多个实例共享它，只多一份骨架实例。

下面这些是"忘了就返工"的那种约定：

* **所有球都按 150px 显示**（球直径就是 150，判定也统一）。角色按"装进一个 150px 圆"来构图：龙要收翅膀、狗蹲着、人画半身。150px 里能一眼分出角色靠的是剪影特征，不是细节。
* **作画 / 导出按显示尺寸的 2 倍**（约 300px），一个角色的图集控制在 `1024²` 以内。Spine 里缩放是免费的，图集大小 ≠ 显示大小，别为了"看起来大"提高导出分辨率。
* **骨架原点放在圆心**（root 落在圆的中心）。这样翻转、缩放、形变都不会跳位；要做朝向就翻 `skeleton.scale.x`，原点在中心才不会偏。导出帧动画同理，按中心对齐。
* **动画里不要带整体位移**。位置永远由 `CharacterBody2D` 决定，动画只做形变、旋转和部件动作，否则会和物理打架。
* **有效剪影控制在 150~180px**，超出的部分当装饰。判定圈固定 90，翅膀伸到 200px 会看起来"明明打到了却没伤害"。
* **每个球仍然保留 `resource/avatar.png`**（从 idle 第一帧截一张就行）。选球界面和 `BallLibrary` 都靠它，Spine 只是 `resource/` 里多出来的文件。
* **导出数据必须是 Spine 4.3**，扩展要的就是 4.3 的运行时数据；把 Spine 升到 4.4 以上导出的数据加载不起来（要升就一起换扩展版本）。骨架用 `.json` 好排查、`.skel` 体积小，两个都认。

### type=2 的球怎么用 Spine

* **文件放哪**：导出的 `.atlas` + 骨架文件（`.json` 或 `.skel`）+ 图集 png，全放进那颗球的 `resource/` 里（跟 `avatar.png` 一个地方）。装配时按球 id 找：目录里第一个 `.atlas` + 第一个 `.json`/`.skel`。
* **动画跟五大状态绑定**：动画名就用状态名，找不到就顺兜底链往下找——

| 状态 | 先找 | 兜底 |
| --- | --- | --- |
| 登场 `Spawn` | `spawn` | `idle` → `move` |
| 移动 `Move` | `move` | `idle` |
| 受控 `Controlled` | `controlled` | `idle` → `move` |
| 攻击 `Attack` | `attack` | `idle` → `move` |
| 死亡 `Dead` | `dead` | `idle` → `move` |

  所以素材只有 `idle` + `attack` 也能跑：登场和移动都放 idle，攻击放 attack。
* **循环**：登场 / 移动 / 受控是循环的；**攻击、死亡只播一遍**（死亡停在最后一帧，球会以那个姿势留在场上）。
* **攻击动画要有时间演**：攻击状态持续多久由攻击组件决定（比如 `2002` 的 `attack_time`），把它配成动画长度就能完整播一遍——这就是下蛋组件为什么需要"攻击状态几秒"这个配置。
* **大小**：靠 Json 的 `spine_scale` 配（`150 ÷ 角色在 Spine 里的高度`）。骨架原点最好放在圆心，缩放和翻转才不会跳位。
* 同一种球只加载一次：两个玩家都选它时共用一份图集，各自只多一份骨架实例。
* **兜底**：资源不全、或者引擎里没有 `SpineSprite`，就自动回落到 `avatar.png`，不会变成一团黑。装配时会在输出里报一句是哪种情况。

## 约定与坑

1. **C# 脚本的文件名必须和类名完全一致（区分大小写）**。不一致时场景引用会报 `Cannot instantiate C# script ... class could not be found`。
2. **必须用带 C# 的引擎**（`梨娅CSharp.exe` 或 `godot.windows.editor.x86_64.mono.exe`）。不带 C# 的版本跑起来会报 `No loader found for resource: ... .cs`。
3. **新放进工程的图片要过一遍导入**（打开编辑器，或跑一次 `--import`）。否则运行时报 `No loader found for resource`。
4. **`ProcessMode` 会被子节点继承**。想让某个节点在暂停时继续工作（比如结算提示），就在**这个节点**上设 `Always`；设在根节点上等于暂停失效，球会继续跑。
5. **检测圈和速度要匹配**。`Area2D` 是逐帧采样的，球太快会整段跳过检测窗口。现在是 120Hz 物理帧率 + 半径 90（对应 900 像素/秒）。再提速要一起调。
6. **组件必须挂在球下面**（组件用 `GetParent()` 拿球）。
7. **通知类事件的处理函数要返回 `true`**，返回 `false` 会阻塞同一事件后面所有组件的收听。
8. **`user://` 和 `res://` 是两份数据**，改仓库里的默认值不会影响已经跑过的机器（只补缺不覆盖）。
9. **编辑器里的"构建"按钮现在用不了**：引擎自带工具要 .NET SDK 10.0.9，这台机器上只装了 9.0.305。编译走命令行 `dotnet build ShineBallGame.csproj`，并把 `NUGET_PACKAGES` 指到 `C:\Users\24807\.nuget\packages`，否则离线解析不到 `Godot.NET.Sdk`。
10. **预制体里的资源是所有球共用的**。形状、贴图、材质这些 `sub_resource` 默认不随实例复制（`resource_local_to_scene = false`），改之前必须先 `Duplicate()`，否则一屏的球会一起变——而且改的是全局资源，切场景都还留着。`BallAssembler.SetCircleRadius` 是按这个写的。
