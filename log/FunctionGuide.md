## 伤害是怎么算的

一次伤害是一个 **`DamageEvent`**（`basic/DamageEvent.cs`）。攻击方调对方的方法是：

```csharp
enemy.TakeDamage(new DamageEvent(enemy, 伤害值, "attack.collision", 自己));
```

`Ball.TakeDamage` 把这个事件交给挨打那颗球身上的**受伤链**（事件名 `take_damage`）。链上的处理函数按优先级**从大到小**跑，**谁返回 `false` 就把后面的全截断**。返回值一路传回来：`true` = 走完了（该扣的血扣了），`false` = 被挡下来了。

| 优先级 | 组件 | 干什么 | 阻塞？ |
| --- | --- | --- | --- |
| 1000 | `3001 defense.conditional_immune` | 在指定状态下挡掉整条链 | 是 |
| 900 | 还没做（沉默：直接扣血，跳过后面的防御） | 优先级占位已留好 | 按需要 |
| 800 | `4004 behavior.poison_damage` | 认出来的毒伤自己扣血，再把剩下的抹成 0（绕过护盾） | 否 |
| 800 | `4008 behavior.true_damage` | 认出来的**真伤**自己扣血、绕过护盾（默认认领域造成的伤害，`domain.`） | 否 |
| 750 | `8xxx` 那一族的领域（`Domain` 基类） | **只记账不改伤害**：把这一次"打进来多少"记到领域外壳上（护盾吃掉的那部分也算），攒够就把领域打碎 | 否 |
| 700 | `3002 defense.shield` | 先掉护盾，没挡完的伤害改小后继续往后传 | 否 |
| 600 | `4002 behavior.poison` | 把球染紫一下，不改伤害 | 否 |
| 500 | `4001 behavior.normal_damage` | 按 `Amount` 真的扣血 | 是（最后一环） |

`DamageEvent` 里有什么：

| 字段 | 说明 |
| --- | --- |
| `Amount` | **还剩多少伤害。处理函数可以改它**，后面的处理函数看到的就是改过的值（减伤、护盾扣掉一部分再放行） |
| `Original` | 原始伤害，别改。要按"本来该打多少"算的时候读它 |
| `Source` | 打人的那颗球。蛋这种"埋伏"没有球当来源时是 `null` |
| `SourceId` | 来源的球 id；蛋填的是**下蛋那颗球的 id** |
| `SourceType` | 哪种组件打的，比如 `attack.collision` / `attack.shift`。环境伤害可以是 `null` |
| `Target` | 挨打的球 |

几条约定：

* **想改伤害就改 `Amount`**，别自己扣血——扣血只有 `4001` 那一步做，而且它会打一句 `[伤害] 谁 -多少（谁打的 的 哪种攻击）` 方便对数。
* **例外只有一个**：`4004` 毒血为了让毒绕过护盾，会自己扣血、并把 `Amount` 抹成 0（见「行为类」里它那一条）。那两行日志是成对的（真实数字在它那行，`[伤害] ... -0` 是 `4001` 的空扣），不是重复扣血。
* **想无敌就返回 `false`**，整条链立刻停（`3001` 就是这么做的）；返回 `true` 表示"这一环处理完了，继续往后传"。
* 为什么伤害要过一条手写的事件链、而不是直接扣血：一次伤害会被好几件事影响——无敌要挡掉它、真伤要无视护盾、护盾要吃掉一部分再把剩下的往后传、持续掉血要顺带扣一点……这些是同一条链上的不同优先级，所以需要"能排序、能中途阻塞"，这就是 `DamagePriority` 存在的原因。
* **领域那一格（750）读的是 `Original` 不是 `Amount`**：护盾吃掉的部分也算"挨了这一下"（不然有盾的家伙领域永远碎不了），而真被无敌挡下来的伤害根本到不了这儿（更前面就阻塞了整条链）。

## 一局是怎么跑起来的

1. `index.tscn` 起来，`IndexManager` 管两个页面：`Index`（主菜单）和 `Select`（选球）。
2. 选球页左右各一个 `BallPicker`，各自选一个球、各自确认；双方都确认后"开始游戏"才可点。
3. 同一个页面的中下方是 `ScenePicker`（扫 `user://scenes/`），点中的就是这一局的场地——场地是两个人的共同环境，所以只选一次、不做"各自确认"，默认第一个。
4. 点开始 → `GameManager.StartGame(球1, 球2, 场地id)` 记下选择并切到 `game.tscn`。
4. `Game` 从 `GameManager` 拿两个 id，用 `BallAssembler` 装配两颗球，摆到左右出生点。
5. 战前互挂：A 的 `enemycomponents` 挂到 B 身上，B 的 `enemycomponents` 挂到 A 身上。
6. 倒计时 3 秒（这期间球是"登场"状态，不会动）→ 对每颗球调 `FinishSpawn()`，球进入"移动"状态开始跑。
7. 只剩一个阵营活着 → 结算：`GetTree().Paused = true` 暂停，显示结果和"按任意处退出"。
8. 按任意键/点任意处 → `GameManager.ReturnToMenu()`（先解除暂停再切场景）回到主界面。

**对局中按 Esc = 暂停**：整棵树冻住（球、倒计时、左右面板全停），暂停面板上有"继续 / 返回主菜单 / 退出游戏"；再按一次 Esc 或点"继续"就回来。"返回主菜单"走的是 `GameManager.ReturnToMenu()`（它自己先解暂停再切场景），"退出游戏"直接 `Quit`。结算之后 Esc 不接管——那时候是提示的"按任意处退出"。主菜单上也有"退出游戏"按钮，主菜单按 Esc 同样能退出。

## 数据放在哪

游戏运行时读的是 `user://` 下的数据，不是仓库里的那份：

| 位置 | 用途 |
| --- | --- |
| `res://assets/data/...` | 仓库里的**默认数据**，只在新玩家第一次运行时补过去 |
| `user://balls/<球id>/` | 运行时真正读的小球数据 |
| `user://scenes/<场地id>/` | 场地数据（`scenedata.json` + `avatar.png`；墙和边框是预制体 `res://assets/scene/arenas/<场地id>.tscn`） |

补数据在 `Bootstrap`（自动加载）里执行，规则是**只补缺、不覆盖**：目标已经存在的文件永远不动，新版本新增的文件会自动补上。

想知道 `user://` 在系统里的真实路径，用 `UserData.Global(UserData.Balls)` 打印一下（Windows 上大概是 `%APPDATA%\Liya\app_userdata\ShineBallGame\balls\`）。

**这带来一个必须记住的后果**：改仓库里的 `balldata.json` 不会影响已经跑过游戏的机器。想立刻生效，直接改 `user://` 里那份，或者把 `user://` 里对应的球目录删掉，让补数据重新复制一次。

## 小球的数据格式

一个球一个文件夹，文件夹名就是球的 id（英文，选球界面和调试信息里都用它）：

```
assets/data/balls/NormalBall/
├── balldata.json
└── resource/
	└── avatar.png
```

`balldata.json` 的字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `name` | 字符串 | 显示名。会填进 `Ball.DisplayName`，数据面板和按钮上显示的就是它 |
| `hp` | 数字 | 血量上限，同时也是开局血量 |
| `type` | 数字 | 外观类型：1 = png，2 = spine（Spine 的文件也放这个球的 `resource/` 里，见「Spine 扩展」） |
| `spine_scale` | 数字 | 只有 `type = 2` 用：骨架整体缩放，配 `想显示多大 ÷ 角色在 Spine 里的高度`（pulipuli 是 0.53） |
| `selfcomponents` | 对象 | **自己的组件**。键是组件编号（字符串），值是这个组件的参数对象 |
| `enemycomponents` | 对象 | **挂到对面身上的组件**，格式同上 |
| `attacks` | 对象 | **招式表**（可省）：招式名 → `{ "time": 演几秒, "anim": 用哪段动画 }`。出招的组件来问"这一招演多久"，外观层来问"配哪段动画"，读法只有 `MoveTable` 一处 |

现成的例子：

```json
{
  "name": "ball",
  "hp": 1200,
  "type": 1,
  "selfcomponents": {
	"2001": { "damage": 100 },
	"1001": { "speed": 900 },
	"4001": {}
  },
  "enemycomponents": {}
}
```

```json
  "attacks": {
	"blue_red": { "time": 0.5 },
	"purple":   { "time": 0.8, "anim": "attack_purple" },
	"domain":   { "time": 1.2 }
  }
```

`"4001": {}` 是空参数写法（普通受伤没有参数）。参数不写就用组件里的默认值。

招式表的两条规矩：`time` 留 0 或不写 = "用这段动画自己的长度"（出招的组件自己决定怎么理解）；
`anim` 不写 = 没有专属动画，退回按状态找（`attack` → `idle` → `move`）。

## 数值基准（咒术回战套件的角色）

**咒术套件的角色以"基准血量 10000"为参照**，顶级角色（五条、宿儺）12000。
其余的数字**跟着血量一起放大**，不然 12000 血配 500 的平A 会变成互捶二十几下的拉锯：

| | 基准 | 五条悟 / 宿儺（顶级） |
| --- | --- | --- |
| 血量 | 10000 | **12000** |
| 平A / 单次斩击 | 约 1000 一级 | 五条 5000（熔断期 1000）；宿儺 解 800×2、捌 500+8% |
| 单发大招 | 3000~8000 | 五条 茈 100000；宿儺 灶開 2000 + 800×刻印 |
| 护盾 / 回复 | — | 五条 护盾 6000、无下限 8000/秒、反转术式 1000/秒 |
| 咒力池 | — | 五条 10000（消耗倍率 0.01）；宿儺 20000（倍率 1、恢复 400/秒） |
| 领域 | — | 无量空处外壳 6000（= 半血）；伏魔御厨子没有壳 |
| 领域必中 | — | 伏魔御厨子 1200/秒（真伤，绕过护盾） |

这几条是**手感参照**，不是硬规矩：具体数字全在各球的 `balldata.json` 里，想调就调。
实测的一局对照（宿儺 vs 五条）：五条的护盾 + 无下限能吃掉宿儺所有的斩击，
所以**斩击打不动他、只有领域能**——这正是原作里的关系（无下限挡斩击、领域里的必中挡不住）；
反过来宿儺没有防御层，被五条的平A（5000 一下）三下就放倒——这一边还欠一轮数值调整。

## 组件总表

编号约定：`1xxx` 移动类，`2xxx` 攻击类，`3xxx` 防御类，`4xxx` 行为类，`5xxx` 形态类，
`6xxx` 控制类，`7xxx` 咒力（资源：给别的组件当底子的池子），`8xxx` 领域。
编号只是**分段**，谁都能引用谁（组件靠 `Requirements` 声明依赖，靠 `Type` 名互相找）。

### 移动类

#### 1001 movement.normal（普通移动）

给一个初速度和初始方向，之后匀速直线前进，撞到东西按反射弹开（相对法线对称），速度大小不变、不衰减。只在**移动状态**下驱动小球，其它状态（登场/受控/攻击/死亡）一律停住。

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `speed` | 数字 | 200 | 速度，像素/秒 |

方向目前**不从 Json 读**：留空就是开局随机挑一个斜方向（20°~70° 的四个象限，保证两个分量都不小，免得两颗球都在水平/垂直线上跑、永远撞不到）。想让它可配，在 `NormalMove.ApplyParams` 里加一行读 `direction` 就行。

#### 1002 movement.jujutsu_motion（苍/赫牵引）

场上有苍球/赫球时**把这一帧的移动接手过来**：被苍吸过去、被赫推开；场上没有就放行，普通移动照常走。
它挂在**被影响的那颗球**身上（五条悟选球时通过 `enemycomponents` 送给对手，和 `6001` 减速是同一种交付方式）——
所以被拽的永远是宿主自己，不存在"去动别人的球"。

它走的是**移动链**（见 `MovePriority` / `move_step`），不是受控状态：
状态还是移动，所以对手照常能出招（受控会把 `BeginAttack` 挡掉，那是控制技不是位移）。
处理完返回 `false` 把普通移动那一环阻塞掉，所以同一帧**不会有两个驱动者**。

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `pull_speed` | 数字 | 600 | 被牵引时的速率（像素/秒），离得越近越接近它 |
| `priority` | 数字 | 100（`MovePriority.Jujutsu`） | 移动链上的优先级，比普通移动（0）大才排在前面 |
| `min_power` | 数字 | 0.05 | 合力小于这个数就当没影响、放行（免得在范围边缘被拖成龟速） |
| `hold_radius` | 数字 | 40 | 贴身刹车半径：贴到苍/赫 中心就停住，而不是冲过去再被拉回来来回抖 |

细节：**只认自己放的苍/赫**（两个五条对打时各瞄各的）；场上有多颗时**挑一颗最管用的**
（强度 × 距离衰减），不是把它们加起来——加起来的话两颗方向相反的会互相抵消、球原地抖。

### 攻击类

#### 2001 attack.collision（碰撞攻击）

敌人进入检测圈就调用对方的 `TakeDamage`，伤害事件里带上来源（打人的球 + `attack.collision`）和伤害值。规则：**不看攻击状态**（任何时候都能打）；撞到自己不算；同阵营（`Group` 相同）不算敌人；自己死了就不再打人。

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `damage` | 数字 | 10 | 每次碰撞造成的伤害 |
| `sound` | 字符串 | 空（不播） | 打到敌人时播的音效文件名或路径 |
| `pitch` | 数字 | 1 | 音效的音高：1 = 原样，**小于 1 更低更沉闷**。同一份素材靠它做出不同手感（盾球是 `hit` + `0.7`） |

它还有个 `Group` 字段，**由装配器从球身上填**（不是 Json），用来判断敌我。

"沉闷"不用另做一份素材：把同一份文件放进球自己的 `resource/`，用 `pitch` 压一档就行——盾球的 `hit.mp3` 就是普通球那一份，压到 0.7 播放。

音效配置长这样：`"2001": { "damage": 100, "sound": "hit.wav" }`。文件放在球自己的 `resource/` 里，找的顺序是：

1. 带协议头的（`user://...` / `res://...`）原样用；
2. 不带协议头的，先找这颗球自己的目录：`user://balls/<球id>/resource/<名字>`；
3. 还找不到就当成 `user://` 下的相对路径：`user://<名字>`。

认 `.wav` / `.ogg` / `.mp3` 三种，直接读文件，不走 Godot 的导入流程（跟 `avatar.png` 一样；放仓库里那份会被补数据复制到 `user://`）。播放时机是**这一下真的打到敌人之后**——撞到自己、同阵营、自己已经死了都不响；默认只放一遍（加载时会把循环强制关掉）。加载和播放都在 `SoundTool` 里，同一个文件只读一次，播放器挂在组件自己身上，一个组件一个。

`sound` 的值**可以不写后缀**：不写的话会依次试 `.ogg` / `.wav` / `.mp3`，所以丢文件进去不用管自己导出的是什么格式。

#### 2002 attack.egg（下蛋攻击）

每隔 `cd` 秒进入一次攻击状态；进入之后过 `windup` 秒产下一颗蛋；攻击状态一共持续 `attack_time` 秒（这段时间是留给 Spine 动画的，没有动画配 0.2 就行），然后回到移动状态。

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `cd` | 数字 | 5 | 两次进入攻击状态的间隔（秒）。它一直在走，前摇和攻击状态里都不暂停 |
| `windup` | 数字 | 1 | 前摇（秒）：进入攻击状态后过多久产蛋 |
| `attack_time` | 数字 | 0.2 | 攻击状态持续多久。实际取 `max(attack_time, windup)`——比前摇短的话，前摇还没走完球就回移动状态了 |
| `egg_id` | 数字 | 无 | 蛋上挂哪个组件（组件编号） |

细节：

* **蛋不是球**：它就是一个普通节点——`Area2D` 当检测圈 + 一张图；长什么样、多大、干什么，全由 `egg_id` 指的那个组件自己搭（见 `2003`）。所以它**不进 `balls` 组、不参与胜负判定、没有血量**，也不是实体（别人碰不到它，只能它碰到别人）。
* 到点了但球不在移动状态（登场中、受控、还在攻击中）时，计时停在 0，等能打的那一刻立刻补上，不会丢这一次。
* 只有死亡会取消这次前摇。"回到移动状态"是攻击演完了，不算打断。
* **蛋一定在攻击状态结束前产出**：windup 到点就产，而攻击状态至少持续到 windup 结束（时长取 `max(attack_time, windup)`）。想让蛋晚点出来就把 windup 配大；只要它不超过 attack_time，攻击状态时长不受影响。
* 蛋的出生位置是**球心往下挪一个球半径**（跟着下蛋那颗球自己的碰撞圈走：100px 的球挪 50、pulipuli 那种 150px 的挪 75），所以它落在球的脚下。
* 蛋还没有自己的数据：想换一种蛋就写一个新组件（`egg_id` 只能带一个组件）。

#### 2003 attack.shift（屎蛋）

**不是组件**，是 `Egg` 的子类（蛋在 `assets/scripts/eggs/` 里，见「如何新增一种蛋」）。撞到敌人时把它切成**受控状态**（减速的入口），然后连着 5 秒每秒造成对方最大生命值 **1/100**（单次最多 100 点）的伤害，效果走完自己消失。

| 写在代码里的默认值 | 值 | 说明 |
| --- | --- | --- |
| `Duration` | 5 | 效果持续几秒：这段时间里对面受控，每秒跳一次伤害 |
| `TickInterval` | 1 | 隔几秒跳一次伤害 |
| `DamageRatio` | 0.01 | 每次跳对方最大生命值的多少（1/100） |
| `DamageCap` | 100 | 单次伤害上限 |
| `Texture` / `Size` | `shit` / 60 | 素材（在**下蛋那颗球的** `resource/` 里找）和显示大小 |

细节：

* **它不是球，也不是实体**：整个东西就是"`Area2D` + 一张图"。不会推开、也不会挡住任何球（**包括下它自己的那颗球**），别人也碰不到它——只有它靠检测圈感知谁撞上来了（检测圈半径 = 显示大小的一半 × 1.2；60px 的蛋就是半径 36）。
* 撞上就立刻疼一下，之后每秒一次；重复撞到会把时间重新计时，不会叠加。
* **撞上就把壳收掉**：触发时把 `scale` 设成 0（Godot 会夹到 `0.00001`，肉眼就是没了），所以它当场"看不见"，而 5 秒的跳伤继续在跑——节点得活着才能继续计时，所以这里**不能**删节点。
* **效果走完自己消失**：目标死了、或者时间到，蛋就 `Destroy()`（内部是 `QueueFree`）。用 `QueueFree` 而不是 `Free`——触发是在 `Area2D.body_entered` 的回调里跑的，当场删会把正在派发信号的那套东西一起掀掉。
* 减速（`6001`）和中毒染色（`4002`）挂在**对面身上**，所以蛋消失不会把效果一起带走。
* 伤害来源记在**下蛋那颗球**头上（`SourceId` 是它的 id，`SourceType` 是 `egg.shit`）——蛋自己不是球，但账算在"谁下的蛋"身上。
* 没人碰过的蛋会一直躺在场上（不挡路、也不算存活、不影响胜负）。要"到期自动消失"就在 `Egg` 基类里加个计时。

#### 2004 attack.basic（平A）

**撞击型的基础攻击**，和 `2001` 是同一套路子（订自己的命中圈 `HitArea`、撞到敌方才打），
区别是它有**咒力那一套**：伤害按咒力状态分两档、有概率打出黑闪。
所以它依赖咒力池（`jujutsu.cursed_energy`），没有池子就装不上。

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `damage` | 数字 | 100 | 平时的基础伤害 |
| `damage_burnout` | 数字 | 100 | **术式熔断**时的基础伤害（五条悟配 100，平时 500） |
| `black_flash_chance` | 数字 | 0 | 这一下出黑闪的概率（0~1），0 = 调试时永远不出 |
| `black_flash_multiplier` | 数字 | 2.5 | 出了黑闪这一下乘多少 |
| `sound` / `pitch` | 字符串 / 数字 | 空 / 1 | 和 `2001` 一样，打中了才响 |

黑闪不是"另一种攻击"，是这一下的**结果**：先按状态取基础伤害、乘上黑闪带来的伤害加成
（`_pool.Multiplier("damage")`，配置里没写这一项就是 1），抽中了再乘黑闪倍率，
最后让咒力池记一层黑闪（`EnterBlackFlash`）——**之后的加成不在这个文件里**，池子按层数自己算。

#### 2005 attack.jujutsu_skill（术式出招）

**每 `cd` 秒按权重随机挑一招打出去**。挑招看的是 `skills` 表（招式名 → 权重，不写就是 1）。

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `cd` | 数字 | 10 | 两次出招的间隔（秒） |
| `cost` | 数字 | 200 | 出一次招花多少咒力（名义值，实际还要乘咒力池的消耗倍率） |
| `skills` | 对象 | `{"blue_red": 1}` | 招式名 → 权重。**权重是相对值**，写 3 和 1 就是 75% / 25% |
| `move` | 字符串 | `blue_red` | 默认那一招叫什么 |
| `distance` / `speed` / `life` | 数字 | 400 / 600 / 30 | 苍/赫 飞多远、多快、留多久 |
| `attack_time` | 数字 | 0.5 | 招式表里没配这一招时，攻击状态演多久 |

现在**写死效果的只有一招：苍/赫**（`blue_red`）——场上有苍就朝它放赫、有赫就朝它放苍，
都没有就苍/赫 和方向都随机；判"场上有苍/赫"时只认自己放的那几颗。

**别的招式名照样演**：付账、进攻击状态、时长和动画都走招式表（见 `MoveTable`），
效果由**认领这个招式名的组件**去做——领域展开就是这么接上的
（招式表里挑中 `domain`，`8001` 订了 `attack_started`，看到自己的名字就展开）。
所以加一招不一定非得改这个文件：在 `skills` 里加名字、再写一个认领它的组件也算数。
⚠️ 代价是"这一招现在能不能用"没人管：比如领域还开着的时候又抽到 `domain`，就是空放
（会白花这个组件的那份 `cost`）。

熔断期间不出招（问咒力池的 `BurnedOut`），计时停在 0，等术式能用了立刻补上；
只在移动状态出招，登场/受控/攻击中到点了就等着。

#### 2006 attack.hollow_purple（虚式茈）

**场上同时有自己放的一颗苍和一颗赫、而且两颗都到位时自动开这一发**，跟随机出招那套没关系，
所以**不看 cd**——苍/赫 一凑齐就放。放的时候两颗苍/赫 在它们的中点"融合"，从那儿朝最近的敌对球
放一颗巨大的茈球（`Purple`：会飞的伤害包，命中走正常受伤链，撞到第一个敌人就消失），
自己进一次攻击状态。

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `cost` | 数字 | 500 | 放一次花多少咒力 |
| `damage` | 数字 | 10000 | 茈球命中的伤害（走受伤链，所以护盾/无敌照样算） |
| `delay` | 数字 | 0.5 | 出来先原地蓄势多久再冲（这段时间不算"飞多久"、也不吃碰撞） |
| `speed` / `life` | 数字 | 2000 / 3 | 飞多快、飞多久没撞到就消失 |
| `size` | 数字 | 280 | 茈球多大（按素材长边算） |
| `move` | 字符串 | `purple` | 招式表里的名字（动画和时长） |

受控期间放不出来（这条判在组件里，不写进状态机）。

#### 2007 attack.dismantle（解）

宿儺那把"普通斩"：**伤害固定，但一次快速出两刀**。两刀各放一道**飞行斩击**
（`SlashProjectile`，见「飞行物」那节），每刀命中各给主人刻一格**斩击刻印**（`7003`）。

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `hits` | 数字 | 2 | 一次出几刀 |
| `damage` | 数字 | 800 | 每一刀的伤害（固定） |
| `cost` | 数字 | 800 | 出一次招花多少咒力（**一次出招只付一次**，两刀算一次钱） |
| `gap` | 数字 | 0.15 | 两刀之间隔几秒（就是"快速斩两刀"的节奏） |
| `speed` / `life` / `size` | 数字 | 1400 / 1.6 / 110 | 斩击飞多快、飞多久消失、斩痕多长 |
| `marks` | 数字 | 1 | 一刀命中刻几格 |
| `lead` | 布尔 | true | 要不要**打提前量**（朝对手"将要去的地方"砍）。关掉就是纯直线瞄准，球在跑就多半落空 |
| `move` | 字符串 | `dismantle` | 招式表里这一招叫什么 |

#### 2008 attack.cleave（捌）

宿儺那把"看人下菜"的斩：**对面越硬砍得越狠**——
`伤害 = base + 对手最大血量 × ratio`（默认 `500 + 8%`：对 12000 血的五条是 1460）。
放出去的也是一道飞行斩击，命中刻一格刻印。

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `base` | 数字 | 500 | 基础伤害（对手再弱也至少这么多） |
| `ratio` | 数字 | 0.08 | 按对手最大血量的比例加伤 |
| `max_damage` | 数字 | 0 | 伤害上限，0 = 不封顶 |
| `cost` / `speed` / `life` / `size` / `marks` / `lead` / `move` | 同上 | 1200 / 1300 / 1.8 / 140 / 1 / true / `cleave` | |

**"越强"怎么算只有一行代码**（`Cleave.DamageAgainst`）：现在读的是对手最大血量，
想改成"按对手护盾""按对手攻击力"就改那一行——这一刀只跟目标有关，不认识伤害链、也不认识别的组件。

#### 2009 attack.fuga（灶開）

宿儺的火焰。**伤害跟着斩击刻印（`7003`）走**：`base + per_stack × 刻印数`
（默认 `2000 + 800/格`：攒到 14 格就是 13200）。所以"先斩、再开"就是它的全部玩法。

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `base` | 数字 | 2000 | 基础伤害（一格刻印都没有时的底线） |
| `per_stack` | 数字 | 800 | **每一格刻印**加多少伤害 |
| `max_damage` | 数字 | 0 | 伤害上限，0 = 不封顶 |
| `cost` | 数字 | 3000 | 放一次花多少咒力 |
| `consume` | 布尔 | true | 放完要不要把刻印清空（默认清——"攒→放"是一个循环） |
| `speed` / `life` / `size` / `splash` | 数字 | 1500 / 3 / 220 / 160 | 火焰飞多快、飞多久、多大、炸开的半径（0 = 只打命中的那一个） |
| `move` | 字符串 | `fuga` | 招式表里这一招叫什么 |

细节：**伤害在放出来的那一刻就算死了**（按当时的刻印数），飞行途中刻印再涨也不算它的；
火焰命中会炸，`splash` 半径内的敌人也各挨一下。它不认识"解"和"捌"，只认识刻印池——
那两个也只知道往池子里刻（**领域里的必中斩 `8004` 也往同一个池子里刻**），谁都不认识谁。

### 防御类

#### 3001 defense.conditional_immune（条件性无敌）

**在指定状态下阻塞整条受伤链**（返回 false），于是这个状态下打不疼它；条件不满足时放行（返回 true），伤害照常往后走。`pulipuli` 用它达成"攻击期间无敌"。

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `state` | 字符串 | `attack` | 哪个状态下无敌：写状态名（不区分大小写），比如 `attack` / `move` / `spawn` |
| `priority` | 数字 | 1000 | 受伤链上的优先级，默认最高（`DamagePriority.AbsoluteImmune`）。想让它排在护盾后面就往下调 |

细节：

* 它只决定"这次伤害算不算"，不改伤害数值——所以放在最前面（1000）就是"这个状态下完全免疫"。
* 挡住的时候会在输出里打一句 `正在Attack，这次伤害挡下`，方便确认它真的生效了。
* 状态名写错不会沉默失败：会警告一句并按默认的 `attack` 处理。

#### 3002 defense.shield（护盾）

挨打时先掉护盾：盾吃掉的伤害不再往下走，**没挡完的那部分才传给血量**（扣血永远由 `4001` 干，这里只改"这次还剩多少伤害"）。它占受伤链的 700 那一格——排在无敌（1000）后面、中毒染色（600）和普通扣血（500）前面。

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `amount` | 数字 | 300 | 护盾上限，开局就是满的 |
| `regen` | 数字 | 0 | 每秒自动回多少护盾，0 = 不回 |

细节：

* **不阻塞**（返回 true）：盾把伤害吃成 0 也让 `4001` 照常走一遍，所以"这一下扣了多少血"只有一处日志（那一行会显示 `-0`）。
* 读的是 `Amount`（前面几环减完之后的值），不是 `Original`——以后有减伤组件时，护盾不该按原始值吃。
* 想读当前盾量（显示、条件判断）用 `Shield.Left` / `Shield.Max`，别去碰私有字段。
* ⚠️ **`regen` 是恒定速率，于是胜负变成一条硬线**：同一个球（血 700 / 撞 60 / 盾 400）对着普通球实测——`regen` 8 → 3 场全输；12 → 盾球赢 3/9；13 → 3/6；14 → 4/6；16 和 20 → 3 场全赢。也就是 12 和 14 之间胜负整个翻过来，中间没有缓冲。想要"势均力敌但不脆"，该改的是**回盾机制**（比如破盾后隔 N 秒才开始回），不是继续调数字。

#### 3003 defense.shield_gauge（护盾条）

把护盾量显示出来，**两处一起**：

* **球身上一根青色细条**，就在血条正下方（没护盾的球看不到它；盾破了显示空条——空着才看得出它在慢慢回）；
* **面板上一行数**（"护盾 320 / 400"，左右面板各按自己的球）。

**依赖护盾组件**：球上没有 `3002` 时，装配器会报错并且不挂它——见「组件基类」里的 `Requirements`。没有参数，写 `"3003": {}` 就行。

细节：

* 那根条的**位置和显隐归外观层管**（`BallLook.PlaceShieldBar` / `BallLook.SetShield`），`ShieldBar.cs` 只管自己的样子（青色、8 像素高）；组件自己只干"每帧把盾量推过去"。
* 面板那一行走的是「把一行数放到面板上（读数）」那套。两处都是**现算**，所以都不会过期。

#### 3004 defense.limitless（无下限）

把护盾变成"打不穿"的那层东西：**只要术式没熔断、咒力还够，就每秒把护盾灌回一大截**，
代价是每秒烧一笔咒力。**它不自己存护盾，而是站在 `3002` 上面**——护盾还是原来那一套
（挨打先掉盾、盾没挡住的才进血），这里只负责往盾里灌。所以前置组件有两个：
`defense.shield`（灌的是它）和 `jujutsu.cursed_energy`（烧的是它、熔断也问它）。

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `regen` | 数字 | 800 | 每秒往护盾里灌多少。"巨量"就是配得比挨打的伤害快得多——打得没回得快就打不穿 |
| `cost` | 数字 | 100 | 每秒烧多少咒力（名义值，实际还要乘咒力池的消耗倍率） |

三条停手规则（按顺序）：**熔断**时完全不灌；**盾满了**不灌（所以盾满的时候咒力一点不掉）；
这一帧该付的咒力**付不起**就不灌（先付账后灌盾，不会白嫖）。
六眼那种消耗倍率（咒力池的 `cost_rate` 配 0.01）让同样的 100/秒实际只花 1/秒，
不用在这里特判——这就是"对六眼来说相当于无损耗"。

### 行为类

#### 4001 behavior.normal_damage（普通受伤）

受伤链的最后一环：按伤害事件里的 `Amount`（**已经被前面几环改过的那个值**）扣血，打一句带来源的 `[伤害]` 日志，然后返回 `false` 阻塞后面的处理函数。装配时被注册到 `EventName.take_damage` 上，优先级 `DamagePriority.NormalDamage`（500）。

没有参数，写 `{}` 或直接省略参数对象都行。

#### 4002 behavior.poison（中毒染色）

受伤链里夹在护盾（700）和一般扣血（500）中间的那一环，优先级 600（`DamagePriority.DamageOverTime`）。它**不阻塞**：只把球染成紫色、过 `tint_time` 秒褪回白色，伤害照旧往后面传、由 `4001` 扣掉。现在伤害事件带来源了，想改成"只有某种来源才紫"（读 `DamageEvent.SourceType`）随时可以。

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `tint_time` | 数字 | 0.2 | 染紫持续多久（秒） |

用的时候注意：**要挂在"被打的那颗球"身上**——直接写它的 `selfcomponents` 可以，由攻击方写在 `enemycomponents` 里让装配器挂过去也可以（`pulipuli` 就是这么配的）。没挂就不会变色，毒伤照走。

#### 4003 behavior.state_sound（进状态放音效）

球**进入指定状态**时播一次音效。`pulipuli` 用它做到"一进攻击状态就出声"。

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `state` | 字符串 | `attack` | 哪个状态下播（状态名，不区分大小写） |
| `sound` | 字符串 | 空（不播） | 音效文件名或路径。**可以不写后缀** |

细节：

* 找文件的方式和 `2001` 的音效完全一样（同一个 `SoundTool`）：先球自己的 `resource/`，再 `user://` 根目录；不写后缀就依次试 `.ogg` / `.wav` / `.mp3`。
* 同一个状态重复进入就每次都播（比如每 8 秒攻击一次就每 8 秒响一次）；没播完会被下一次打断——一个组件只有一个播放器。
* 它只是"进状态就出声"，和攻击组件没有耦合：换个攻击组件、或者手动切状态，它照样工作。

#### 4004 behavior.poison_damage（毒血）

**让"毒"绕过护盾、直接进血**。挂在**被打的那颗球**身上（攻击方写在自己的 `enemycomponents` 里，装配时挂到对面），占受伤链的 800 那一格——比护盾（700）先跑，所以护盾来不及吃。

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `source_prefix` | 字符串 | `egg.` | 哪种伤害算毒：按伤害事件里的 `SourceType` 做前缀匹配（蛋类都是 `egg.xxx`，屎蛋是 `egg.shit`） |

细节：

* **它自己扣血**：认出是毒就从血量里扣掉，然后把 `Amount` 抹成 0 再往下传——护盾看到 0 就不吸收，`4001` 照常打一行 `-0`。**不阻塞**（返回 true），所以中毒染色（600）还会照常亮一下。
* ⚠️ 这是「扣血只有 `4001`」的**唯一例外**，日志要两行一起看：真实数字在 `[behavior.poison_damage] ... 中毒 -N（绕过护盾）`，`[伤害] ... -0` 是 `4001` 的空扣。
* 现在的用法：`pulipuli` 的 `enemycomponents` 里挂着它，于是它的蛋（`egg.shit`）那点跳伤直接进血——**这就是"毒克盾"**。实测盾球对它：护盾吸收 0，毒伤 700 全进血，3 场全输（`pulipuli` 除了毒没有别的伤害来源，所以盾球这一身盾在它面前完全没用）。

#### 4005 behavior.reverse_technique（反转术式）

**血不满就自己回血**，回多少血就烧多少咒力。**效率写在咒力池里**（`jujutsu.cursed_energy` 的
`reverse_rate`，单位是"每秒回多少血"）：效率是 0 就等于"不会反转术式"——组件挂着也不干活，
这就是"会不会"的开关。前置组件只有一个：`jujutsu.cursed_energy`。没有自己的参数。

两条要在意的地方：

* **它是被血量变化叫醒的，不是每帧盯着血量看**：平时它把自己的 `_PhysicsProcess` 关掉
  （空闲时零次调用）；谁的血量一变（`hp_changed` 事件）它才看一眼，该回血才打开。
  血回满、或者咒力不够了，就再关掉。**先付账后回血**：付不起这一帧就不回、并且停手，
  重新回血的时机是下一次血量变化。
* 烧咒力走的是咒力池的倍率（`cost_rate`），这里只报"我回了多少血"。
  五条悟配了反转效率 100/秒 + 黑闪每层再 +50。

#### 4006 behavior.sandbag_damage（沙包受伤）

练球用的"打不死"：扣血照扣，**但血量永远不会掉到 `min_hp` 以下**，所以挂了它的球死不了。
拿它试伤害、试连招、量数值最合适（沙包球就是它 + `4007`）。

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `min_hp` | 数字 | 1 | 扣完至少留多少血。默认 1：永远差一口气 |

⚠️ 它是 `4001` 的**替代品，不是搭档**：两者都是"受伤链的最后一环"（优先级 500、都返回 false 截断），
**一颗球上只能挂一个**，两个都挂会各扣一次血。
唯一的漏洞是 `4004` 毒血——它自己直接扣血、绕开这条链，所以能把这层保底打穿。

#### 4007 behavior.hp_refill（回满血）

血量掉到 `trigger_hp` 及以下时，等 `delay` 秒**把人回满**——沙包球拿它当"打不烂的靶子"：
一巴掌拍到底 → 停一下（让人看得见到底了）→ 满血重来。它不碰咒力，回血不要钱。

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `trigger_hp` | 数字 | 1 | 血量掉到这个值及以下就触发（默认和沙包受伤的保底对齐） |
| `delay` | 数字 | 1 | 触发之后等几秒再回满，0 = 立刻回满 |

和反转术式一样是**被血量变化叫醒的**（`hp_changed`），平时 `_PhysicsProcess` 关着。
人已经死了就不回满——死亡是终点，回满血也不该把人从死亡状态里拉回来。

#### 4008 behavior.true_damage（真伤）

**这一类伤害绕过护盾、直接进血**——和 `4004` 毒血是同一格（受伤链 800）、同一套路子，
区别只在"认哪种来源"：毒血认 `egg.`（蛋），真伤认 `domain.`（领域）。

谁需要它：**领域里的必中**。领域里的斩击是"已经命中"的，护盾那套（无上限每秒灌盾）
挡不住它——原作里五条在伏魔御厨子里也只能靠反转术式硬扛，就是这个道理。
所以宿儺在自己的 `enemycomponents` 里给对面挂上它、`source_prefix` 配 `"domain."`：
于是"领域造成的伤害"绕过护盾，"平A/斩击造成的伤害"照常被护盾吃。**要不要真伤是数据说了算**，
领域本体（`8001`/`8003`）和领域效果（`8004`）都不认识这个组件。

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `source_prefix` | 字符串 | `domain.` | 哪种伤害算真伤：按 `DamageEvent.SourceType` 做前缀匹配 |

⚠️ 和毒血一样，它是"扣血只有 `4001`"的**例外之一**：自己扣血、把 `Amount` 抹成 0，
日志打的是 `[behavior.true_damage] ... 吃真伤 -N（绕过护盾）`。
同一格上挂两个认同一个前缀的组件会各扣一次，别这么配。

### 形态类

#### 5001 shape.circle（圆形碰撞箱）

把球的碰撞圈 / 命中圈改成指定半径。**不写参数就什么都不做**，用预制体里那套默认圆——默认值只留在 `NormalBall.tscn` 里，代码和场景不会各存一份数字（跟数据的"只补缺、不覆盖"一个道理）。

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `radius` | 数字 | 0（= 用预制体的 50） | 物理碰撞圈半径 |
| `hit_radius` | 数字 | 0（= 用预制体的 60） | 命中检测圈半径。只写了 `radius` 时按 1.2 倍跟着走，保住两个圈的比例 |

例：`"5001": { "radius": 60 }` → 碰撞圈 60、命中圈 72。

为什么留这个口子：个别球的判定比例可能不一样（龙比虫子占地大一点），或者运行中要改形状（成长、缩水、护盾期间判定变大）——后者改预制体根本做不到。

**注意：装配时必须先复制形状再改。** 预制体里那个 `CircleShape2D` 是所有球共用的同一个资源（`resource_local_to_scene = false`），直接改半径会让场上一屏的球、乃至之后每个新球一起变。`BallLook.SetCircleRadius` 就是干这个的。

#### Spine 外观（不是组件，没有编号）

`type = 2` 的球由**外观层**自动处理（`BallLook.Apply` → `SpineLook`）：在球的 `resource/` 里找 Spine 资源，然后跟着球的五个状态切动画。**它不是组件**——Json 里写 `"5002": {}` 会报"没有编号为 5002 的组件"。

显示多大由 `balldata.json` 的 `spine_scale` 决定，细节见「Spine 扩展」里的「type=2 的球怎么用 Spine」。

### 控制类

#### 6001 control.slow（减速）

挂在**被打的那颗球**身上——攻击方在自己的 `enemycomponents` 里配好，装配时被挂到对面。

它跟移动类组件是一个套路，只是各管一个状态：

| 状态 | 谁来驱动球 | 速度 |
| --- | --- | --- |
| 移动（`Move`） | `1001 movement.normal` | 全速 |
| 受控（`Controlled`） | `6001 control.slow` | 原先的 30% |

所以减速**不是靠挨打触发**的，是靠状态：蛋碰到球时把球切成受控（`Ball.BeControlled`），这个组件听见状态变化就接管这一段的移动——方向不变、速度乘 `speed_scale`；受控时间走完（自动回移动状态）再把速度还原。中途撞墙照样反弹（和 `1001` 共用 `BallMovement`）。

**球身上一个控制类组件都没挂时，受控就是"定身"**（没人驱动它，球停住）。也就是说：受控状态只说"谁被接管了"，**接管之后怎么动，由控制类组件决定**。

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `priority` | 数字 | 0 | 注册到状态变化事件时的优先级（别的状态监听都是 0，一般不用改） |
| `speed_scale` | 数字 | 0.3 | 速度压到原先的多少 |

细节：

* 接管那一刻记下"原先的速度"当基准，撒手时还原，所以受控期间反复挨打也不会越减越慢（30% 再 30% 就成 9%）。
* 静止的球（速度为 0，比如还没过登场倒计时）没什么可减的，接管了也不会动。
* 同一颗球挂**两个**控制类组件时，**每帧只有仲裁出来的那一个驱动球**（`BallControl.PickDriver`：先比类别优先级、同类别再比强度、最后按挂载顺序），弱的那条不会跟着一起推。但"接管那一刻压速度"还是每个控制类组件各做一次，所以两个减速会叠乘（0.3 × 0.3），别这么配。

#### 6002 control.mute_attack（受控禁手）

**自己处在受控状态时，把自己的命中圈（`HitArea`）关掉**——不能靠碰撞还手。

为什么需要它：撞击型的攻击（`2001` / `2004`）是**不看状态的**，它们订的是"自己的命中圈被碰到"，
所以球被定住了照样能撞人。这一条把"被控住就还不了手"补上：受控一进就关掉命中圈，出控再打开。
**于是"定身"才是真的定住，而不是"站着不动但一身是刺"。**

它是**通用件**，不特判任何领域：只要是受控状态就生效，来源可以是领域压制（`8002`）、
屎蛋、以后的眩晕……想让谁守这条规矩就给他装上（无量空处的受害者是靠五条悟的
`enemycomponents` 把这一条一起送过去的）。没有参数。

关的是 `HitArea.Monitoring`（**自己**感知别人），不碰碰撞形状：球该被撞还是会被撞，
只是它自己不再主动打人。术式那一类不用管——`2005`/`2006` 本来就只在移动状态出招。

### 咒力类（7xxx）

咒术那一套的**公共底子**。所有术式组件（无下限、反转术式、平A、出招、领域……）都要求球上先有
`7001`，并在自己的 `Bind` 里按 `Type` 名把它找出来用（`Requirements` 里写 `jujutsu.cursed_energy`）。

#### 7001 jujutsu.cursed_energy（咒力池）

一个咒术师的咒力池，**全项目只有这一份状态**：咒力量、恢复速度、消耗倍率、反转术式效率、
黑闪层数与加成表。

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `amount` | 数字 | 1000 | 咒力上限，开局就是满的 |
| `regen` | 数字 | 0 | 每秒自动回多少咒力 |
| `cost_rate` | 数字 | 1 | **咒力消耗倍率**（咒力操控程度）：实际消耗 = 名义消耗 × 这个值。六眼配 0.01 = 只花百分之一 |
| `reverse_rate` | 数字 | 0 | 反转术式效率：**每秒回多少血**。0 = 不会用（`4005` 挂着也不干活） |
| `state` | 字符串 | `normal` | 咒力状态：`normal` / `domain_boost` / `burnout` / `black_flash`（下划线可有可无、不区分大小写） |
| `black_flash` | 对象 | 空 | 黑闪加成表：属性名 → **每层**加多少（五条悟配的是 `{"reverse_rate": 50}`） |

**状态是互斥的"此时此刻是哪种模式"**，只存在这个池子里：别的组件要用就来问（`BurnedOut`），
不自己存一份（存两份一定会出现"这个说熔断了、那个说没有"）。

**黑闪不走状态，走"层数 + 每层加成表"**——因为状态互斥、加成叠加：
熔断期间打出黑闪，要是写进状态就会把熔断顶掉，无下限马上又开始回盾。
所以池子用 `BlackFlashStacks`（本局累加、不清零），加成按 `层数 × 每层值` 算：

* 池子自己管的三个属性直接生效：`reverse_rate`（反转效率）、`cursed_regen`（咒力恢复）、`cost_rate`（消耗倍率）；
* 别人的属性（伤害、护盾上限……）用 `Bonus("名字")` / `Multiplier("名字")` 来拿一格；
* 表里写什么名字都行，不挑不拣，**想加新加成就多写一行**。

两个口子：`TrySpend(名义消耗)` 花咒力（会乘 `cost_rate`，不够就返回 false、一点不扣）、
`Restore(量)` 补咒力。**熔断不在这里拦人**——`TrySpend` 只看够不够，术式自己看 `BurnedOut`
决定要不要停手（反转术式熔断期间照样能用，就是这个道理）。
`EnterBurnout(秒)` 是"进熔断，到时候自己回正常"（领域收场用的就是它）。

#### 7002 jujutsu.cursed_energy_gauge（咒力条）

把咒力池显示成**球身上一根紫色细条 + 面板上一行数**（"咒力 1000 / 1000"）。
依赖 `7001`，没池子就不挂。没有参数，写 `"7002": {}`。
它也是"**加一根条不用动预制体**"的样板：条是它自己在装配时造出来、挂进球身条区（`BallLayout`）的，
尺寸由条自己带，排在哪儿归条区——以后要显示别的资源照这个再写一个即可。

#### 7003 jujutsu.slash_mark（斩击刻印）

**宿儺的专属资源池**：每一次斩击落下去就刻一格，刻得越多，**灶開**（`2009`）那一下越狠。
它和咒力池是同一个定位——**全项目只有这一份数字**，加格的（解 `2007`、捌 `2008`、
领域里的必中斩 `8004`）和读数的（灶開）都不自己存一份，都来找它。

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `max` | 数字 | 0 | 上限，0 = 不封顶 |
| `decay` | 数字 | 0 | 每秒自动掉几格，0 = 不掉（默认：攒起来就一直留着） |

接口三个：`Add(几格)`、`Consume()`（灶開放完清空）、`Count`。面板上自动多一行"斩击刻印 N"。
别的组件要找它用 `SlashMark.Find(球)`，别写死从哪个节点拿。

### 领域类（8xxx）

领域的规矩（开、壳、范围、熔断）全在基类 `Domain` 里，**一个领域 = 一个基类的子类 + 一组 Json 参数**。
详细的用法见下面「如何新增一种领域」，这里只说组件分工：

| 编号 | 类型名 | 干什么 | 挂在哪 |
| --- | --- | --- | --- |
| `8001` | `domain.unlimited_void` | 无量空处（五条悟的领域），就是"**配置好的基类**" | 自己的 `selfcomponents` |
| `8002` | `domain.control` | **领域的效果**：站在敌方生效中的领域里、自己又没有领域 → 被压住（定身） | 对方的 `enemycomponents`（和 `1002` 一个交付方式） |
| `8003` | `domain.malevolent_shrine` | 伏魔御厨子（宿儺的领域）：**开放型**——没有外壳、打不碎，只会到期 | 自己的 `selfcomponents` |
| `8004` | `domain.malevolent_shrine_slash` | 伏魔御厨子的**必中斩**：罩住的人每秒挨一次斩，并且给领域持有者刻一格刻印 | 对方的 `enemycomponents` |

**为什么效果要单独一个组件**：领域本体只管"场上有一个圈、圈在这儿、壳还剩多少、什么时候碎"，
谁在圈里会怎样由这个组件决定。所以同一个领域想换效果不用动领域本体；这个组件也能被别的领域复用。

`8002 domain.control` 的参数：

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `duration` | 数字 | 100000 | 被压住多久（秒）。默认 ≈ 这一局就废了（无量空处就是"落地即定胜负"） |
| `release_when_free` | 布尔 | false | 罩住你的领域消失/被压碎之后要不要放开。无量空处配 false = 中了就锁死；给"回血跟得上就还能打"的那类领域留的口子是 true |

它是**控制类组件**：类别 `stun`、类别优先级 200（压过减速的 100），
由 `BallControl.PickDriver` 把方向盘判给它、它把速度清零——所以哪怕受害球上还有减速，
也还是"真的不动"。要能还手得另外装 `6002`（默认不装，谁被控谁装）。

`8004 domain.malevolent_shrine_slash` 的参数：

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `interval` | 数字 | 1 | 隔几秒挨一下 |
| `damage` | 数字 | 1200 | 每一下的伤害（走正常受伤链，所以护盾/无敌照常算——除非对面另装了 `4008` 真伤） |
| `marks` | 数字 | 1 | 这一斩给**领域持有者**刻几格 |

它和 `8002` 用的是同一套判定（`DomainQuery`：`CoveringField` 找罩住我的敌方领域、
`Contesting` 看我自己有没有在顶），区别只是判定成立之后干什么：
`8002` 定身，`8004` 斩一下并记刻印。**所以"领域里会发生什么"是可以随便换的**，判定不用重写。

#### 领域基类 `Domain` 的参数和规则

`8001`（以及以后每一个领域）都是它的子类，参数都写在球 Json 的组件参数里：

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `open` | 布尔 | false | **开放型领域**：没有外壳——打不碎，也不参与优先级/范围的比较（只按时间到期） |
| `shell_hp` | 数字 | 0 | 外壳能扛多少伤害。**0 = 用持有者最大血量的一半**（五条 1200 血 → 600） |
| `radius` | 数字 | 360 | 半径：场（和外壳）就在这个半径上 |
| `priority` | 数字 | 10 | 优先级：**数字大的压数字小的**，见下面第 3 条 |
| `duration` | 数字 | 99 | 持续几秒 |
| `cost` | 数字 | 600 | 展开一次花多少咒力（名义值，实际要乘咒力池的消耗倍率） |
| `windup` | 数字 | 0.6 | 前摇：进攻击状态之后过多久真正展开（留给手势/动画） |
| `move` | 字符串 | `domain` | 招式表里这一招叫什么（出招那边选中它 = 展开） |
| `follow` | 布尔 | true | 对手开领域时要不要立刻跟进 |
| `burnout_time` | 数字 | 20 | 收场之后术式熔断多久 |
| `attack_time` | 数字 | 0.8 | 招式表里没配这一招时，攻击状态演多久 |
| `ring_width` | 数字 | 2 | 环宽（像素） |

四条规则（都在基类里实现，子类不用重复写）：

1. **什么时候开**：场上出现**敌对领域就立刻跟进**（每帧检查，条件一满足就开）；
   平时它算招式表里的一招——出招的组件挑中 `move` 这个名字、照常起手，
   领域订了 `attack_started` 去认领，然后展开。两条路最后都走"付账 → 前摇 → 展开"。
   登场中/受控/熔断时开不了，会等下一帧再看。
2. **外壳怎么掉血**：领域生效期间，持有者挨的伤害记一笔账（受伤链的 750 那一格，
   读 `Original`：被护盾吃掉的那部分也算，被无敌挡下来的不算），攒够 `shell_hp` 就把领域打碎。
   **伤害照常进持有者的血**，这一层不替人挨打。
3. **范围互相压**：非开放型领域每帧算一次有效半径 = `半径 × (1 − 优先级差 ÷ 10)`，
   差 10 以上就是 0 —— 领域当场被对面**覆盖**（碎掉）。开放型不参与这套比较。
   被压小/回弹时会在日志里打一句"范围变成 N"。
4. **收场进熔断**：时间到、被打碎、被覆盖，三种都算结束，都让咒力池熔断 `burnout_time` 秒：
   期间术式停手（`2005` 不出招、`3004` 不灌盾）、平A 掉到熔断那一档。这就是领域的代价。
   持有者死掉则直接散场，不走熔断。
5. **必中先打领域（领域互相抵消）**：对面的领域必中打过来时，**先算在保护持有者的那个领域上**
   （`Domain.Absorb`），挡下来了人就不吃这一下：
   * 非开放型：记到外壳的账上，攒够就碎——**两个领域对撞时，谁的壳先撑不住谁先暴露**；
   * **开放型**：不吃伤害，但**照样把必中抵消掉**——这就是开放型的强势之处（打不碎、一直替持有者挡），
     代价是被覆盖时（优先级差 ≥ 10）它会当场碎，之后必中就直接落到人身上了；
   * **正在开（前摇里）也算"我在用领域顶"**（`Domain.Pending` + `DomainQuery.Contesting`）：
     两个领域同时开时，先展开的那一方不该在对方的前摇窗口里把对面锁死——不然"同时开互相抵消"
     就变成拼手速了。**没开、也没在开**才真的吃效果。

**领域自己不带效果**：它只管"场上有一个圈、壳还剩多少、什么时候碎"。
谁在圈里会怎样由给对面的组件决定（见 `8002`）——所以想改"控多久""还能不能还手"，改的是 Json。
球身上的表现：开领域时自己造一根"领域条"挂进球身条区（和咒力条一个套路，预制体不用动），
面板上多一行读数（"剩 42s 壳 300 / 600"），没展开时写"未展开"。

## 飞行物（会飞的伤害包）

**茈、宿儺的斩击、灶開的火焰是同一类东西**：朝一个方向直飞，撞到敌对阵营的球就算命中，
伤害走正常的受伤链，然后自己消失。所以它们共用一个基类
`assets/scripts/projectiles/DamageProjectile.cs`——飞行、判定、留场计时、阵营判断、
"撞自己人不算命中"全在基类里，子类只管两件事：

| 文件 | 是谁 | 只管什么 |
| --- | --- | --- |
| `projectiles/Purple.cs` | 虚式茈 | 紫色、出来先蓄势、蓄完重新索敌 |
| `projectiles/SlashProjectile.cs` | 解/捌的斩击 | 画成一道细长的斩痕、朝目标直飞、**命中给主人刻一格刻印** |
| `projectiles/FireArrow.cs` | 灶開的火焰 | 一团火、命中炸开（`splash` 半径内的敌人也各挨一下） |

预制体在 `assets/scene/projectiles/` 下（`Purple.tscn` / `Slash.tscn` / `FireArrow.tscn`，
都只有一个挂了脚本的 `Area2D` 根节点——**图是代码画的**，不占素材、不用过导入）。

放一发飞行物的写法（`解` 就是这么写的）：

```csharp
var slash = scene.Instantiate<SlashProjectile>();
slash.Name = DamageProjectile.Numbered("斩击·解");   // 带序号，不然同一帧两发同名会被引擎改名
slash.Position = _ball.Position;
slash.Launch(_ball, 伤害, Type, 方向, 速度, 留场, 大小, 颜色, 刻几格);
parent.AddChild(slash);                                // 进树之前 Setup/Launch，和蛋、苍赫一个位置
```

两个现成的工具（都在基类上）：

* `DamageProjectile.LeadDirection(从我, 目标球, 速度)` —— **打提前量**：朝对手"将要去的地方"打。
  球一直在跑，直着打过去多半落空（实测：不打提前量时宿儺的斩击基本全空）。
  想要"纯直线、能躲"的飞行物就别调它，直接用 `目标位置 − 我位置`。
* `DamageProjectile.NearestEnemyOf(球, 阵营, 位置)` —— 挑最近的敌人（"打谁"只有这一份实现）。

**想加一种新的飞行物**：在 `projectiles/` 下写一个 `DamageProjectile` 的子类
（要改长相就覆盖 `DrawShape()`，命中之后要额外干点什么就覆盖 `OnHitBall()`），
在 `assets/scene/projectiles/` 下配一个只挂脚本的 `.tscn`，然后在放它的组件里
`Instantiate` + `Launch` 就行。**基类和别的地方都不用动。**

## 组件基类 BallComponent

所有组件都挂在球节点下面，继承 `BallComponent`，必须自描述：

| 成员 | 说明 |
| --- | --- |
| `Id` | 唯一编号，Json 里用的就是它 |
| `Type` | 类型名，形如 `"attack.collision"` |
| `DisplayName` | 显示名（默认等于 Type） |
| `Description` | 一句话说明 |
| `Requirements` | 前置组件：**写组件的 `Type` 名**（比如 `"defense.shield"`），可以写好几个。装配时检查，缺了就不挂这个组件并报错。写的是依赖，不是处理顺序 |
| `ApplyParams(字典)` | 装配时把 Json 里的参数读进自己的字段 |

组件内部用 `GetParent()` 拿球，所以**必须挂在球下面**。

## 状态机

状态是定死的几种（`BallState`），不开放给用户自定义，因为所有组件都靠"现在是什么状态"决定自己该不该干活：

| 状态 | 含义 |
| --- | --- |
| `Spawn` | 登场：刚上场，还没开始行动；开局就是它 |
| `Move` | 移动：自己动的球，移动类组件只在这个状态驱动小球 |
| `Controlled` | 受控：控制类组件只在这个状态响应输入（见 `6001 control.slow`；**被控住还想不能还手就再挂 `6002`**） |
| `Attack` | 攻击：有动作的攻击走这里（见 2002）。移动类组件在这期间不驱动球，所以球会停住，时长由攻击组件定 |
| `Dead` | 死亡：终点，不再接受任何状态切换 |

规则：

* 当前状态是**私有**的，外面只能通过公开方法改，或者订阅状态事件；
* 每次改状态之前先判断当前状态（比如死人不能被拉回移动状态）；
* 血量扣到 0 或以下会自动进入 `Dead`，同时把速度清零；
* 公开方法：`FinishSpawn()`（登场 → 移动）、`BeControlled(duration, repeat)`（进入受控，`ControlRepeat` 有 `Reset`/`Add`/`Ignore` 三种处理方式）、`EndControl()`（提前结束受控）、`BeginAttack(招式名, 时长, repeat)`（进入攻击，时间到自动回移动状态；只有移动中能进）；
* **受控状态只负责"换人驱动"**：移动类组件在受控状态下不驱动球，所以这段时间由控制类组件接手（见 `6001 control.slow`，慢速前进）。一颗球没挂任何控制类组件时，受控就是定身。
* **受控不等于"不能还手"**：撞击型攻击不看状态，想让他打不出人得挂 `6002 control.mute_attack`（见那一节）。
* 只读查看：`Ball.State`。

## 小球身上的事件总线

每个球有一个 `BallEvent`（`Ball.Events`），组件之间通过它通信。注册的处理函数按 `priority` 从大到小执行，**返回 `false` 就阻塞**后面的处理函数，返回 `true` 继续。

| 事件 | 载荷 | 说明 |
| --- | --- | --- |
| `take_damage` | `DamageEvent`（还剩多少 + 原始值 + 来源） | 扣血走这里。整条链由优先级决定谁先处理，谁返回 `false` 谁截断 |
| `state_changed` | 新的 `BallState` | 状态变化。通知类事件，处理函数一律返回 `true`，否则会把后面组件的收听一起堵掉 |
| `hp_changed` | `float`（**这次变了多少**：正数回血、负数掉血；当前血量读 `Ball.Hp`） | 血量真的变了才响。想"只在受伤/回血时做点什么"就订它，别每帧比血量——`4005` 反转术式、`4007` 回满血平时都靠它把自己叫醒 |
| `move_step` | `float`（这一帧的秒数） | **移动链**：球每帧在移动状态下发的"这一帧谁来驱动我"。按优先级从大到小跑，返回 `false` 就把后面的挡住（苍/赫 在场时就是这么把普通移动阻塞掉的） |
| `attack_started` | `string`（招式名，可能是空的） | 球开始演一招时发（**含换招**）。外观层拿它去招式表找动画；"认领某一招"的组件也订它——领域展开（`8001`）就是这么知道"该我上场了" |
| `attack_interrupted` | `string`（被打断的那一招） | 当前这一招被新招**打断**时发（`AttackRepeat.Interrupt`），给还没生效的效果一个收尾的机会。正常演完、被覆盖（`Replace`）都不发 |

伤害链的优先级表（`DamagePriority`，数值越大越优先）：

| 数值 | 名称 | 说明 |
| --- | --- | --- |
| 1000 | `AbsoluteImmune` | 绝对免疫（无敌）：阻塞，不扣血 |
| 900 | `Silence` | 沉默：直接扣血，跳过后面的防御 |
| 800 | `TrueDamage` | 真伤：无视护盾等 |
| 750 | `DomainShell` | 领域外壳：只记账（读 `Original`），攒够就把领域打碎；非阻塞、不改伤害 |
| 700 | `Shield` | 护盾（非阻塞） |
| 600 | `DamageOverTime` | 持续扣血（阻塞） |
| 500 | `NormalDamage` | 一般扣血 |

## 移动链（这一帧谁来驱动球）

球的移动以前是"每个移动组件自己在 `_PhysicsProcess` 里推一步"，两个移动组件挂上去就会各推一步
（双倍位移）。现在统一成一条链：**球每帧在移动状态下发一个 `move_step` 事件**，
移动类组件按优先级订阅，**同一帧只有一个说了算**（谁先处理谁就把这一帧的移动接手下来，
返回 `false` 就把后面的挡住）。

| 数值 | 名称 | 谁 | 行为 |
| --- | --- | --- | --- |
| 100 | `Jujutsu` | `1002 movement.jujutsu_motion` | 场上有苍/赫 时整段接管（返回 `false`） |
| 0 | `Normal` | `1001 movement.normal` | 普通移动：推进 + 撞墙反弹，链条的收尾（返回 `false`） |

想加"在普通移动之上再叠一点"的修正层：优先级排在普通移动**前面**、处理完返回 `true` 放行；
想加"整段接管"的（冲刺、瞬移、牵引）：排在前面、处理完返回 `false` 挡住。
注意 `move_step` **只在移动状态发**：登场/受控/攻击/死亡时谁都叫不起来——
受控期间的驱动权还是 `BallControl` 那套仲裁说了算（见 `6001`）。

## 把一行数放到面板上（读数）

组件想让自己的一行数出现在左右面板上，就往球身上的读数表里登记一条：

```csharp
// 在自己的 Bind 里（装配期）登记："标签 + 现算函数"
ball.Readouts.Add(new BallReadout("护盾", () => $"{shield.Left:0} / {shield.Max:0}"));
```

规矩只有三条：

* **登记的是函数，不是值。** 面板每 0.1 秒现问一遍，所以显示永远不过期（存值就又变成"事件流"，漏一次就永久显示错的）。这还顺手解决一个坑：同一个球上，你依赖的那个组件的 `Bind` 可能还没跑（取决于 Json 书写顺序），登记那一刻去读它的值会读到初始值——`3003` 第一次写就踩了这个，所以它登记的是 `() => ...`，不是当时的值。
* **面板不认识任何具体组件。** 它只照着 `Ball.Readouts` 画行、现拉值，所以以后再加一种要显示的读数（护盾、连击、冷却……），`BallDataPanel` 一个字都不用改。
* **行是在面板绑定时建好的。** 现在的用法是"装配期登记、绑定时建行"；比赛中间再登记不会显示，真需要那样得把面板改成每次对着表补行。

## 小球预制体

所有球共用 `assets/scene/NormalBall.tscn`，贴图在运行时按球自己的目录换：

| 节点 | 类型 | 说明 |
| --- | --- | --- |
| 根节点 | `CharacterBody2D` | 挂 `Ball.cs`，碰撞、移动都靠它 |
| `Body` | `Sprite2D` | 贴图。装配时换成 `resource/avatar.png`；场景里那张只是默认值 |

| `HitArea` | `Area2D` + `CollisionShape2D` | 碰撞检测：圆，半径 60。比球体稍大是故意的——`MoveAndCollide` 会把球停在"刚好接触"的位置，等大就永远差一点点触发不了。半径同样可以被 `5001` 改 |

## 如何自定义一个小球

1. 在 `assets/data/balls/` 下新建一个文件夹，名字就是球的 id（例如 `FastBall`）。
2. 放一个 `balldata.json`，按上面的字段写：名字、血量、外观类型、自己的组件、给对面的组件。
3. 放 `resource/avatar.png`——它同时是选球界面的头像和球在场上用的贴图，建议用正方形。要音效就再往 `resource/` 里放音频文件（`.wav` / `.ogg` / `.mp3`），然后在组件参数里写 `"sound": "文件名"`。
4. 把项目跑一次（或者删掉 `user://balls/<球id>/` 再跑），补数据会把新球复制到 `user://`。
5. 进游戏，选球界面会自动多出一个按钮，点它就能用这个球开打。

想让球有别的行为，就往 `selfcomponents` 里加组件编号和参数；想给对面添堵，就写到 `enemycomponents` 里。

## 如何新增一个组件

1. 在 `assets/scripts/components/` 下写一个类，继承 `BallComponent`，文件**必须**和类同名（例如 `Burn.cs` → `class Burn`）。
2. 挑一个没被占用的编号（1xxx 移动 / 2xxx 攻击 / 3xxx 防御 / 4xxx 行为 / 5xxx 形态 / 6xxx 控制），实现 `Id`、`Type`、`Description`。
3. 自己的参数写成公开字段，并重写 `ApplyParams` 从字典里读（用 `JsonTool.GetValue(parameters, "键", 默认值)`）。
4. 有前置组件（没它这个组件就跑不起来）就重写 `Requirements`，写上那些组件的 `Type` 名
   （例如 `new[] { "defense.shield" }`）。装配器会检查：球上没有、这一批里也没有，
   就**报错并且不挂这个组件**。写的是依赖，不是顺序。
5. 要接线就重写 `Bind(Ball ball, string configId)`：注册事件、连信号、改形状都在这里。
   `configId` 是"哪颗球的 Json 配出了我"——`enemycomponents` 送人时是**送出去的那颗球**，
   找素材/找音效要用它，别用现在挂着的这颗。
   因为装配是"这一批**先全挂到球上**、再挨个 `Bind`"，所以 `Bind` 里按 `Type` 找兄弟组件是安全的——
   找得到与否跟 Json 里的书写顺序无关。
   ⚠️ 接线写 `Bind`，别写 `_Ready`：`Bind` 在装配时跑（球还没进场景树），而血条是在**所有组件
   `Bind` 完之后**按最终碰撞圈摆的——`_Ready` 太晚，`5001` 改的形状会被血条漏掉。
6. 在 `ComponentLibrary.Create` 里加一个 `case 你的编号: return new 你的组件();`。
7. 现在就能在 `balldata.json` 里用编号引用它了。

**装配器不用改**：`BallAssembler` 只做"建 → 填参数 → 查前置组件 → 先全挂上 → 再挨个 `Bind`"，
它不认识任何具体组件；事件也由组件自己注册，装配器不碰。

## 如何新增一种蛋

蛋不走数据配置（蛋和蛋的差别可能很大：会飘的、会炸的、会孵小兵的），**一种蛋 = 一个类**：

1. 在 `assets/scripts/eggs/` 下写一个类，继承 `Egg`，文件同名（例如 `BombEgg.cs` → `class BombEgg`）。
2. 覆盖 `OnHit(Ball enemy)` 写自己的效果；外观覆盖 `Texture` / `Size`（素材默认在**下蛋那颗球的** `resource/` 里找）。
3. "消失"用 `HideShell()`（把壳收掉、节点留着继续干活），活干完用 `Destroy()`（排到帧末删自己）。
4. 在 `EggLibrary.Create` 里加 `case 编号: return new 你的蛋();`，然后在球的 `2002 attack.egg` 的 `egg_id` 里填这个编号。

## 如何新增一种领域

**一个领域 = 继承 `Domain` 的一个类 + 一组 Json 参数**（规则全在基类里，子类只填默认值、定外观）。
五条悟的无量空处（`8001`）就是最短的例子，一共三十来行。

1. 在 `assets/scripts/components/jujutsu/<角色>/` 下写一个类，继承 `Domain`，文件同名
   （例如 `MalevolentShrine.cs` → `class MalevolentShrine`）。
2. 实现 `Id`（8xxx 里挑一个没被占的）、`Type`（`domain.xxx`）、`DisplayName`、`Description`，
   `Requirements` 写上 `CursedEnergy.TypeName`（展开要花咒力）。
3. 想换外观就覆盖 `CreateField()` 返回一个 `DomainField` 的子类
   （照 `assets/scripts/domains/UnlimitedVoidField.cs` 抄：改配色、覆盖 `DrawInside(半径)` 画圈里的装饰），
   想只换颜色也可以直接覆盖 `FillColor` / `RingColor`。
4. 在构造函数里给几个默认值（半径、优先级、时长、消耗……），**Json 里的同名键会覆盖它**。
5. 在 `ComponentLibrary.Create` 里加 `case 编号: return new 你的领域();`。
6. 在球的 `selfcomponents` 里写上编号和参数，在 `attacks` 里给它的招式名配个时长（动画可选），
   再把这个招式名写进 `2005 attack.jujutsu_skill` 的 `skills` 权重表里——这样平时会随机开。
7. 领域**对别人干什么**是另一回事：照 `8002 domain.control` 那样写（或直接用）一个组件，
   放进球的 `enemycomponents` 送过去。想定身 + 不能还手就是 `8002` + `6002` 两件套。
   想要**伤害型**的领域就照 `8004` 写：判定用 `DomainQuery.CoveringField` / `Contesting`，
   打之前先问一句"对面自己的领域要不要替它挡"（`Domain.Absorb`）——挡下了就别打人身上。
   至于要不要**绕过护盾**，那是给对面的 `4008` 真伤组件的事（`source_prefix` 配成你这个领域的类型名前缀）。

基类的四条可配规则（`open` / `shell_hp` / `radius` / `priority`）和其余参数（`duration` / `cost` /
`windup` / `move` / `follow` / `burnout_time` / `ring_width`）见上面的「领域基类 `Domain` 的参数和规则」。
**开放型（`open: true`）**适合做"打不碎、靠时间磨"的领域：没有壳、不参与优先级压缩，
但会替持有者抵消对面的必中；`8003` 伏魔御厨子就是这么配的（半径 450、优先级 20、99 秒）。
**测试**：想让它必定展开就把 `2005` 的 `skills` 只留这一个招式名、`cd` 配小（比如 5），
跑一局看日志里的"展开……"和"范围变成……"两行。

## Spine 扩展

编辑器能用的 Spine 是官方 GDExtension，放在 `addons/spine-godot/`（`4.3-4.7.1 stable`，带编辑器/调试/发布三套、各平台都在）。

* **不用在 `project.godot` 里"启用"它**：引擎扫到 `.gdextension` 就会加载，`.godot/extension_list.cfg` 只是自动生成的缓存（`.godot/` 本来就不入库）。
* 认得的后缀，导入后分别是这两种资源：

| 后缀 | 导入成 |
| --- | --- |
| `.atlas` | `SpineAtlasResource` |
| `.spine-json`、`.spjson` | `SpineSkeletonFileResource` |
| `.skel`、`.spskel` | `SpineSkeletonFileResource`（二进制） |

* 用法：新建一个 `SpineSkeletonDataResource`（存成 `.tres`），把 `atlas_res`、`skeleton_file_res` 指过去，再赋给 `SpineSprite` 节点的 `skeleton_data_res`；播放动画走 `get_animation_state()`。
* 新放进工程的 `.atlas` / `.spine-json` 和图片一样要过一遍导入（打开编辑器，或跑一次 `--import`），否则运行时加载不到。

### 动画与美术的约定

球的外观资源放在 `user://balls/<球id>/resource/` 下，**不走 Godot 的导入流程**（导入器只在 `res://` 生效），所以运行时要现场构建：`SpineAtlasResource.load_from_atlas_file(路径)` + `SpineSkeletonFileResource.load_from_file(路径)` → 塞进 `SpineSkeletonDataResource` → 赋给 `SpineSprite.skeleton_data_res`，动画用 `get_animation_state().add_animation(名, 延迟, 循环, 轨道)`。按球 id 缓存一份，同一种球的多个实例共享它，只多一份骨架实例。

下面这些是"忘了就返工"的那种约定：

* **默认按 100px 装**：`type = 1` 的贴图球，装配时会把素材按长边统一缩到 100px（素材画多大都行）；`type = 2` 的 Spine 球用 `spine_scale` 自己定（`pulipuli` 是 0.53 ≈ 150px）。
* 角色按"装进对应的圆"来构图：默认 100px 的球（碰撞圈半径 50 / 命中圈 60），`pulipuli` 那种大一点的角色用 `5001` 覆盖成 75 / 90，也就是 150px 的圆。圆里能一眼分出角色靠的是剪影特征，不是细节。
* **作画 / 导出按显示尺寸的 2 倍**（约 300px），一个角色的图集控制在 `1024²` 以内。Spine 里缩放是免费的，图集大小 ≠ 显示大小，别为了"看起来大"提高导出分辨率。
* **骨架原点放在圆心**（root 落在圆的中心）。这样翻转、缩放、形变都不会跳位；要做朝向就翻 `skeleton.scale.x`，原点在中心才不会偏。导出帧动画同理，按中心对齐。
* **动画里不要带整体位移**。位置永远由 `CharacterBody2D` 决定，动画只做形变、旋转和部件动作，否则会和物理打架。
* **有效剪影控制在自己的判定圈以内**（默认 100px 的球就是 100~120px，`pulipuli` 是 150~180px），超出的部分当装饰。视觉超出判定太多，就会看起来"明明打到了却没伤害"。
* **每个球仍然保留 `resource/avatar.png`**（从 idle 第一帧截一张就行）。选球界面和 `BallLibrary` 都靠它，Spine 只是 `resource/` 里多出来的文件。
* **导出数据必须是 Spine 4.3**，扩展要的就是 4.3 的运行时数据；把 Spine 升到 4.4 以上导出的数据加载不起来（要升就一起换扩展版本）。骨架用 `.json` 好排查、`.skel` 体积小，两个都认。

### type=2 的球怎么用 Spine

* **文件放哪**：导出的 `.atlas` + 骨架文件（`.json` 或 `.skel`）+ 图集 png，全放进那颗球的 `resource/` 里（跟 `avatar.png` 一个地方）。装配时按球 id 找：目录里第一个 `.atlas` + 第一个 `.json`/`.skel`。
* **动画跟五大状态绑定**：动画名就用状态名，找不到就顺兜底链往下找——

| 状态 | 先找 | 兜底 |
| --- | --- | --- |
| 登场 `Spawn` | `spawn` | `idle` → `move` |
| 移动 `Move` | `move` | `idle` |
| 受控 `Controlled` | `controlled` | `idle` → `move` |
| 攻击 `Attack` | `attack` | `idle` → `move` |
| 死亡 `Dead` | `dead` | `idle` → `move` |

  所以素材只有 `idle` + `attack` 也能跑：登场和移动都放 idle，攻击放 attack。
* **循环**：登场 / 移动 / 受控是循环的；**攻击、死亡只播一遍**（死亡停在最后一帧，球会以那个姿势留在场上）。
* **攻击动画要有时间演**：攻击状态持续多久由攻击组件决定（比如 `2002` 的 `attack_time`），把它配成动画长度就能完整播一遍——这就是下蛋组件为什么需要"攻击状态几秒"这个配置。
* **大小**：靠 Json 的 `spine_scale` 配（`想显示多大 ÷ 角色在 Spine 里的高度`）。pulipuli 的素材高约 284，想显示 150 就配 **0.53**；它同时还用 `5001` 把碰撞圈改回 75 / 90。骨架原点最好放在圆心，缩放和翻转才不会跳位。
* 同一种球只加载一次：两个玩家都选它时共用一份图集，各自只多一份骨架实例。
* **兜底**：资源不全、或者引擎里没有 `SpineSprite`，就自动回落到 `avatar.png`，不会变成一团黑。装配时会在输出里报一句是哪种情况。

## 约定与坑

1. **C# 脚本的文件名必须和类名完全一致（区分大小写）**。不一致时场景引用会报 `Cannot instantiate C# script ... class could not be found`。
2. **必须用带 C# 的引擎**（`梨娅CSharp.exe` 或 `godot.windows.editor.x86_64.mono.exe`）。不带 C# 的版本跑起来会报 `No loader found for resource: ... .cs`。
3. **新放进工程的图片要过一遍导入**（打开编辑器，或跑一次 `--import`）。否则运行时报 `No loader found for resource`。
4. **`ProcessMode` 会被子节点继承**。想让某个节点在暂停时继续工作（比如结算提示、对局的暂停面板 `PauseMenu`），就在**这个节点**上设 `Always`；设在根节点上等于暂停失效，球会继续跑。
5. **检测圈和速度要匹配**。`Area2D` 是逐帧采样的，球太快会整段跳过检测窗口。现在是 120Hz 物理帧率 + 半径 60（对应 900 像素/秒）。再提速要一起调。
6. **组件必须挂在球下面**（组件用 `GetParent()` 拿球）。
7. **通知类事件的处理函数要返回 `true`**，返回 `false` 会阻塞同一事件后面所有组件的收听。
8. **`user://` 和 `res://` 是两份数据**，改仓库里的默认值不会影响已经跑过的机器（只补缺不覆盖）。
9. **编辑器里的"构建"按钮现在用不了**：引擎自带工具要 .NET SDK 10.0.9，这台机器上只装了 9.0.305。编译走命令行 `dotnet build ShineBallGame.csproj`，并把 `NUGET_PACKAGES` 指到 `C:\Users\24807\.nuget\packages`，否则离线解析不到 `Godot.NET.Sdk`。
10. **预制体里的资源是所有球共用的**。形状、贴图、材质这些 `sub_resource` 默认不随实例复制（`resource_local_to_scene = false`），改之前必须先 `Duplicate()`，否则一屏的球会一起变——而且改的是全局资源，切场景都还留着。`BallAssembler.SetCircleRadius` 是按这个写的。
11. **UI 用 `z_index` 压住球**。`game.tscn` 里的倒计时、结果、提示、左右数据面板都设了 `z_index = 10`，球是默认的 0——不然球会飘到面板和文字上面（球的节点是运行时才加进去的，排在场景节点后面）。
12. **组件接线写在 `Bind`，不要写在 `_Ready`**。`Bind` 在装配时跑（球还没进场景树），血条是在所有组件 `Bind` 完之后按最终碰撞圈摆的，所以"改形状"必须赶在血条前面。
13. **草稿素材放 `draft/`**（已 gitignore，里面有 `.gdignore` 所以引擎不扫描）。正式素材放球自己的 `assets/data/balls/<球id>/resource/`，跑一次会自动补到 `user://`；找法统一在 `BallLibrary.Find`（头像、音效、Spine、蛋的素材都走它）。
14. **领域是"跟着球走"的**：场（`DomainField`）是施术者的子节点，所以施术者跑到哪儿圈就到哪儿。
    "谁在圈里"用**圆心距离**判定，**没有物理碰撞体**——Godot 没有环形的碰撞形状，而且真做成实心的话
    对方球会被挡在外面、领域效果永远触发不到。那道 2px 的环是**画出来的**（`DrawArc`），
    所以想改粗细/配色改的是 `ring_width` 和 `DomainField` 的颜色，不影响规则。
15. **领域外壳记的是"打进来的伤害"，不是"掉了多少血"**：受伤链 750 那一格读 `Original`，
    所以护盾吃掉的部分也算——不然有护盾/无下限的球，领域永远碎不了。
    而真被无敌挡下来的伤害到不了这儿（更前面就阻塞了整条链）。
16. **领域收场一定熔断**（时间到 / 被打碎 / 被更强的领域覆盖，三种都是），
    熔断期间 `2005` 不出招、`3004` 不灌盾、平A 掉到 `damage_burnout` 那一档。
    想改熔断多久就配领域的 `burnout_time`。持有者死了则直接散场，不走熔断。
17. **领域开着的时候再抽到 `domain` 这一招是空放**：`2005` 不会问"这一招现在能不能用"，
    它会照常付账、照常演动作，只是领域那边看自己已经开着就不重复展开。
    不想看到就把它在 `skills` 里的权重配小（或者以后做"招式可用性"）。
18. **"被控住不能还手"要单独装 `6002`**：撞击型攻击（`2001`/`2004`）不看状态，
    受控的球照样能撞人。领域压制定身（`8002`）只管"不能动"，两件套一起给才叫真的制服。
19. **`_PhysicsProcess` 不是白给的**：`4005` 反转术式、`4007` 回满血这类"平时没事干"的组件
    都把自己关掉（`SetPhysicsProcess(false)`），靠事件叫醒。新写这种组件时记得
    **在 `_Ready` 里关**（脚本里写了 `_PhysicsProcess` 的话，引擎会在进树时自动打开它，
    装配期关的那次会被盖掉）。
20. **领域对撞的三件事**（`8002` / `8004` 都靠它，改动要一起想）：
    ① 对面有领域（或者**正在开的前摇里**）→ 必中打不到人身上；
    ② 非开放型拿外壳去挡（挡着挡着壳就碎了）；开放型不吃伤害但**照样抵消**；
    ③ 优先级差 ≥ 10 时弱的那一方当场被覆盖——它一碎，必中就直接落到人身上了。
    这三条都在 `Domain.Absorb` 和 `DomainQuery.Contesting` 里，别在效果组件里各写一份。
21. **领域里的必中伤害默认是真伤**（宿儺给对面挂了 `4008`、前缀 `domain.`）：绕过护盾直接进血。
    不挂它的话，五条的护盾 + 无下限（8000/秒回盾）会把伏魔御厨子那 1200/秒全吃掉、
    血一点都不掉——领域就成摆设了。要不要真伤是**数据**说了算，领域本体不认识它。
22. **飞行物要打提前量**：球一直在跑，直着飞过去基本全空（实测宿儺的斩击不打提前量时命中率极低）。
    用 `DamageProjectile.LeadDirection`，想要"能躲的直线弹"就别用。
    同一帧放出多发时记得用 `DamageProjectile.Numbered` 起名，不然第二发会被引擎改名叫 `@Area2D@19`。
